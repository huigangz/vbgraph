# P2.4.2 — Sidecar reader + `ScipLastRefresh` type

**Status**: complete
**Date**: 2026-05-24
**Decisions**: design § P2.3 sidecar at `.codegraph/scip-last-refresh.json` (written by P2.3.3, consumed here).

## Changes

### `src/types.ts`

`ScipLastRefresh` interface — mirrors the sidecar schema written by `CodeGraph.refreshScip`:

```ts
interface ScipLastRefresh {
  refreshedAt: string;     // ISO 8601
  scipPath: string;
  command: string;
  filesCovered: number;
  durationMs: number;
  lastError: string | null; // added 2026-05-25 (post-ship review round 3);
                            // semicolon-joined derived-data errors from the
                            // last refresh, or null on a clean refresh.
                            // `getLastScipRefresh` normalizes legacy sidecars
                            // without this field to `lastError: null`.
}
```

JSDoc documents: schema is informal, write failures are non-fatal, status treats absent/corrupt as "never refreshed".

### `src/index.ts` — `CodeGraph.getLastScipRefresh()`

Reads `.codegraph/scip-last-refresh.json`, parses, validates required fields, returns the typed object OR `null`.

Three failure modes all collapse to `null`:
- File doesn't exist (`!fs.existsSync(sidecarPath)`) — common on fresh projects.
- JSON parse error (corrupt or partial write) — caught by `try/catch`.
- Missing required field (sidecar from a future schema with renamed fields) — explicit shape check.

This collapses the three cases on purpose: status doesn't need to distinguish "never refreshed" from "sidecar broken". Users wanting the distinction can `cat` the file.

`ScipLastRefresh` added to the import block.

## Why explicit shape validation

Without it, a partially-written sidecar (e.g. truncated mid-write) could surface to status as a JS object with `undefined` fields → `formatDuration(undefined)` blows up downstream. Explicit field-by-field type checks → null → status falls back to "never refreshed". Defensive, ~5 lines.

## Validation

- `npx tsc --noEmit` clean.
- Functional regression in P2.4.6.

## Risk callouts

- **TOCTOU race**: `fs.existsSync` then `fs.readFileSync` — if a concurrent refresh deletes the file between the two calls, the read throws `ENOENT`. Caught by the `try/catch` → null. Acceptable.
- **Large sidecars**: not a concern — schema is a fixed 6 fields (5 + `lastError` since review round 3), file is well under 1 KB.
- **Symlink attack**: if a malicious symlink at `.codegraph/scip-last-refresh.json` points to a sensitive file (`/etc/shadow`), we read it. Mitigation: `.codegraph/` is user-owned; the threat model is local-only. Out of scope for this method.
