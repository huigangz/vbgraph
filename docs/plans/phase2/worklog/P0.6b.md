## Findings — the pinned grammar is a weak community grammar

Probing the actual parse trees revealed real limitations of `cfca210`:

- **Works** (verified): `file`, `Module`, `Class`, `Namespace`, `Interface`, `Sub`/
  `Function` (as `method`), `Property`, `Friend`->internal visibility, per-file `Imports`,
  `contains` containment edges, and **file-local call edges** (see the follow-up below).
- **`Inherits` / `Implements` do not parse** — the grammar misparses them as
  `field_declaration` nodes with `MISSING ":"`, so no extends/implements reference is
  produced. The core `extractInheritance` was still wired for `inherits_clause` so a
  future grammar bump (or a better grammar) starts working without code changes.
- **`Structure` / `Enum`** parse into `structure_block` / `enum_block`. Their members are
  *direct children* (no `body` field), which the generic `extractStruct` / `extractEnum`
  did not expect — so no node was produced. **Resolved 2026-05-21** — see below.

## Follow-up applied (review finding #2)

A review found Tier-0 VB produced no relationship edges at all. Root cause for **calls**:
VB `method_declaration` has no `body` field, and `extractMethod` skips a method whose body
field is absent (unlike `extractClass`, which falls back to the node). Adding
`resolveBody: (node) => node` to `vbnetExtractor` makes the method's statements (and the
`invocation` calls in them) get walked — **file-local calls now extract** (`tier0-vbnet.test.ts`
asserts `Sub Main` -> `Helper`).

`Inherits` / `Implements` remain grammar-blocked. Per the review's accepted option, **P0
ship gate 1 is rewritten** in `codegraph-scip-ingestion.md` to scope VB inheritance edges
as SCIP-only (Tier 1); Tier-0 VB delivers symbol nodes + containment + file-local calls +
`Imports`.

## Follow-up resolved — Structure / Enum extraction (2026-05-21)

`Structure` / `Enum` now extract on the Tier-0 path. The cause was an
inconsistency in the core, not the grammar: `extractEnum` already resolved a
bodyless declaration through the optional `resolveBody` hook, but `extractStruct`
still did a plain `getChildByField(node, 'body')` and bailed when the field was
absent. VB `structure_block` has no `body` field (members are direct children),
so it always bailed. `extractStruct` now uses the same `resolveBody` fallback —
a one-site change, inert for every language that does not define `resolveBody`.
`tier0-vbnet.test.ts` covers it (`Structure` with fields + `Enum` with members);
the doc-comment on `vbnetExtractor` is corrected.

`Inherits` / `Implements` stay **Tier-1 (SCIP) only** by decision — the pinned
community grammar misparses them into `field_declaration` + MISSING/ERROR
tokens, unrecoverable from the Tier-0 tree. `extractInheritance` stays wired for
an `inherits_clause` node, so a future grammar lights it up with no code change.
The single remaining `it.skip` in `tier0-vbnet.test.ts` documents this.

**Open (optional):** evaluate a higher-quality VB.NET tree-sitter grammar that
parses `Inherits`/`Implements` — would close the last Tier-0 VB gap.
