# P1.5 PR-5 — react migration

**Status**: complete
**Date**: 2026-05-23

## What landed

`src/resolution/frameworks/react.ts` rewritten as a Phase 3 resolver
with Node-kind-discipline applied:

- `detect` — unchanged.
- `synthesize`:
  - **Components**: same four regex patterns as legacy `extract`
    (function / arrow / forwardRef / memo), same "afterMatch contains
    JSX" heuristic, emits `kind='component'` nodes with namespaced IDs
    `framework:react:component:<file>:<name>:<line>` and provenance
    `framework:react`. Inherent tag `react:component` attached to each
    synthesized component.
  - **Next.js routes**: pages/ and app/ conventions retained, synthesized
    as `kind='route'` nodes. Namespaced ID + provenance.
  - **Hooks as tags, not nodes** (Node-kind discipline): the legacy code
    created `kind='function'` nodes with id `hook:…` for every `use*`
    name. Now we tag the *existing* function node via
    `graph.getNodesByKind('function').filter(/^use[A-Z]/)`. This makes
    the hook discoverable by tag without inventing a phantom node that
    duplicates the real function row.
- `augment` — omitted. The legacy `resolve` paths (component / hook /
  context by-name resolution) are covered by P0.5b's scope resolver and
  the import resolver for ts/js. Component→hook call edges remain in
  the tree-sitter `calls` graph; they don't need a framework convention
  edge to be discoverable.
- `extract` and `resolve` fields removed.

## Tests

`reactResolver.extract` smoke test replaced with three tests on
`reactResolver.synthesize`:

1. SynthesizeResult shape (smoke).
2. Component node emission for a function-returning-JSX case.
3. `react:hook` tag emission on an existing `function` node named
   `useFoo` (drives the `getNodesByKind('function')` path).

All 62 tests across `frameworks.test.ts` + `p1-phase3-orchestrator.test.ts` pass.

## Notes

- The Next.js route detection includes `.ts` / `.js` files when they live
  under `pages/` or `app/`. The regex stripper choice (`'typescript'` vs
  `'javascript'`) is based on extension only — close enough for the
  pages convention; SCIP / tree-sitter handle the real language for
  caller analysis.
- A future component→hook augment could emit `references/convention`
  edges by re-scanning component bodies for `use[A-Z]\(` invocations.
  Deferred — the existing tree-sitter `calls` graph already captures
  these.
