## Notes

- The legacy `extract` field stays on the `FrameworkResolver`
  interface (`@deprecated`) so the framework-resolver type still
  permits it. Removing the field entirely would break the existing
  "FrameworkResolver.extract interface" type-smoke test and any
  external code that declares an `extract` field for compatibility.
  The runtime no longer calls `fw.extract`, which is what matters.
- Strategy-1 `framework.resolve` in `ReferenceResolver.resolveOne` is
  still live and guarded by `if (!framework.resolve) continue`. Three
  resolvers (vue, svelte, rust) intentionally retain `resolve` for
  framework-built-in symbols. Strategy-1 becomes dead code only if
  those three also retire their `resolve` hooks; that requires a
  parallel mechanism (global "framework-provided names" registry)
  which is P3 work.
- The CHANGELOG entry's version number (0.8.0) reflects the size of
  the API change (synthesize/augment is a new public hook on
  `FrameworkResolver`). It's a suggestion — the actual bump and
  publish flow is the user's call per the CLAUDE.md house rules.
