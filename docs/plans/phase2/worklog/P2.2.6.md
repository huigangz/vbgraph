## Test harness notes

- **Direct QueryBuilder access** — not driven through `ExtractionOrchestrator.sync()`. The sync rewrite is indirectly covered by the existing `extraction.test.ts` suite (which still passes for non-SCIP-covered files) plus the helper tests here. End-to-end sync flow would require a fixture with both `.scip` ingestion and file modification — that lives in the broader sync test suite, deferred to P2.6.
- **`markFileScipCovered` test helper** directly inserts into `scip_documents` because there is no public helper outside the persister pipeline. Documented in the test source.
- **`readRawNode` / `readRawEdge` helpers** bypass `rowToNode`/`rowToEdge` so tests can assert on raw `stale`/`staleness_visible` integer columns — necessary to distinguish hidden-stale (0) from visible-stale (1) from fresh (NULL/0).
- **Each test opens its own DB** via `openFreshDb()`. WASM-backed (better-sqlite3 not installed in this env); tests are slower (~100ms per case) but uniform.

## Sample failures the suite would catch

1. **Forgetting cache invalidation**: cached `getNodeById('n')` returns the fresh row after `markScipFileStale('F.cs', 0)` → "hides a cached fresh node after marking it stale" fails.
2. **Removing scip-empty-fallback from `SCIP_FILE_PROVENANCES`**: bulk-mark misses fallback rows → "includes fallback rows in the bulk mark" fails.
3. **Switching edge mark to symmetric (target-side too)**: "does NOT mark edges TARGETING the changed file from elsewhere" fails — explicit regression for Decision 2.
4. **`deleteFileTreeSitterRows` using exact `provenance='tree-sitter'`**: fallback row survives the delete → "removes only tree-sitter% rows" deletes count drops to 1 (not 2).
5. **`storeExtractionResult` shadow mode accidentally calling `deleteFile`**: the end-to-end shadow flow would lose the SCIP row → "SCIP rows survive..." fails because `readRawNode(scipId)` returns null.
