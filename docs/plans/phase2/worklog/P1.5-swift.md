# P1.5 PR-13 — swift migration (uikit + swiftui + vapor)

**Status**: complete
**Date**: 2026-05-23

## What landed

`src/resolution/frameworks/swift.ts` rewritten (was 429 lines, now ~245).
Three resolvers in one file, one PR.

### swiftui (`swiftUIResolver`)

- `detect` — unchanged.
- `synthesize`:
  - SwiftUI `View` structs → `component` nodes (already in NODE_KINDS),
    namespaced `framework:swiftui:view:…`, with inherent tag
    `swiftui:view`.
  - `@main App` structs → **tag** `swiftui:app` + `entry-point` on the
    existing struct/class node (Node-kind discipline: an App struct IS
    its source-code struct).
- `resolve` removed.

### uikit (`uikitResolver`)

- `detect` — unchanged.
- `synthesize`: **tag-only** — `uikit:viewcontroller` on existing class
  nodes whose declaration matches `: UIViewController`,
  `uikit:uiview` on `: UIView` subclasses. Zero synthesized nodes.
  Per the plan's Node-kind discipline: a UIViewController IS its source
  class; we tag rather than duplicate.
- `resolve` removed.

### vapor (`vaporResolver`)

- `detect` — unchanged.
- `synthesize`: `app.METHOD("/x", use: handler)` → `route` node,
  namespaced `framework:vapor:route:…`, provenance `framework:vapor`.
- `augment`: per-route source-line re-parse, single-candidate
  resolution, `references/convention` edge + `vapor:controller` +
  `route-handler` tags.
- `resolve` removed.

## Tests

- 1 `vaporResolver.extract` test + 1 strip-comments regression rewired
  to `synthesize`. No swiftUI / uikit-specific test changes needed (the
  existing tests don't probe their `extract` or `resolve` hooks).

All 64 tests across `frameworks.test.ts` + `frameworks-integration.test.ts`
+ `p1-phase3-orchestrator.test.ts` pass.

## Notes

- The biggest discipline win: uikit no longer synthesizes phantom
  `kind='class'` nodes for UIViewControllers/UIViews (which would have
  duplicated the tree-sitter-extracted class). The migration moves
  those to tags, which is the right shape per the plan.
- Swift has no scope resolver yet — recall on the dropped
  suffix-resolve patterns is lost, same as laravel/rails. Documented in
  [P1.5-laravel.md](P1.5-laravel.md) / [P1.5-rails.md](P1.5-rails.md).
