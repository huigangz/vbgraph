# P2.2.4 + P2.2.5 — Sync rewrite + branch-switch threshold

**Status**: complete
**Date**: 2026-05-24
**Decisions**: design doc Decisions 1 (shadow write path), 6 (branch-switch defense), the write-path diagram.

Two sub-tasks merged in one worklog because the sync rewrite (P2.2.4) and the branch-switch defense (P2.2.5) read the same `maxStaleFilesPerSync` config field and modify the same code site at [src/extraction/index.ts:1278+](../../../src/extraction/index.ts#L1278).

## Changes

### `src/types.ts`

`CodeGraphConfig.maxStaleFilesPerSync?: number` (default 50). Documented with the bulk-vs-per-file tradeoff. Defaulted in `DEFAULT_CONFIG`.

### `src/extraction/index.ts`

#### `storeExtractionResult` — new `mode: 'replace' | 'shadow'` parameter

```ts
private storeExtractionResult(
  filePath: string,
  content: string,
  language: Language,
  stats: fs.Stats,
  result: ExtractionResult,
  mode: 'replace' | 'shadow' = 'replace',
): void;
```

- `'replace'` (default, all existing callers unchanged): calls `deleteFile(filePath)` first — provenance-blind wipe.
- `'shadow'`: skips the deleteFile call. The caller has already done a provenance-scoped `deleteFileTreeSitterRows` AND `markScipFileStale(filePath, 0)`, so SCIP rows survive (hidden by `freshPredicate`).

The two-line change at lines 1099-1101: `if (existingFile && mode === 'replace')` instead of `if (existingFile)`.

#### `indexFileShadow(relativePath)` — new public method

Drop-in counterpart to `indexFile` that uses `storeExtractionResult(_, _, _, _, _, 'shadow')`. Same read-file → detect-language → extractFromSource flow; only the storage mode differs.

Public (not private) so future tests can drive it directly.

#### Sync loop rewrite (lines ~1343-1413)

Replaces the old single-loop `await this.indexFile(filePath)` with:

```ts
// Partition changed files into SCIP-covered vs not.
const scipChanged: string[] = [];
const nonScipChanged: string[] = [];
for (const filePath of filesToIndex) {
  if (this.queries.isFileScipCovered(filePath)) scipChanged.push(filePath);
  else nonScipChanged.push(filePath);
}

// Branch-switch defense.
const maxStale = this.config.maxStaleFilesPerSync ?? 50;
const bulkBranchSwitch = scipChanged.length > maxStale;
if (bulkBranchSwitch && scipChanged.length > 0) {
  const summary = this.queries.bulkMarkScipFilesStale(scipChanged, 1);
  logWarn(`[codegraph] Branch switch detected (${summary.filesAffected} ...)`);
}

// Per-file loop.
for (each filePath) {
  if (SCIP-covered AND bulk-branch-switch) continue;
  if (SCIP-covered) {
    if (shadow-capable language) {
      markScipFileStale(F, 0);
      deleteFileTreeSitterRows(F);
      await indexFileShadow(F);
    } else {
      markScipFileStale(F, 1);  // no extraction; visible-stale
    }
    continue;
  }
  // Non-SCIP-covered: existing replace path.
  await indexFile(filePath);
}
```

### `isShadowCapable` decision

The audit (P2.2.0) noted `isLanguageSupported(lang)` from `grammars.ts` already encodes the "has a grammar" question. The design doc's `isShadowCapable` is literally a synonym. Decision: **use `isLanguageSupported` directly** rather than add a wrapper. Saves a layer, keeps the intent self-documenting at the call site.

### Bulk-branch-switch warning

CLI warning emitted via `logWarn` (existing logging facility):

```
[codegraph] Branch switch detected (N SCIP-covered files changed;
  threshold = 50). Skipping per-file shadow extraction; SCIP data is
  now marked stale-but-visible. Run 'codegraph scip-refresh' to
  restore precision.
```

Single warning per sync, not per-file. The user sees exactly one line per branch switch.

## Why `isFileScipCovered` is called twice per file

The partition loop calls it once, and the per-file loop calls it again. Two-pass design:
1. First pass: build the `scipChanged[]` set to know if `bulkBranchSwitch` applies.
2. Second pass: branch per-file based on coverage + bulk decision.

Could be optimized to a single pass + a `Set` of SCIP-covered paths, but:
- `isFileScipCovered` is a single-row prepared-statement lookup (~5µs).
- For 50 files, the double-call adds 250µs — irrelevant.
- The two-pass structure makes the bulk-threshold decision explicit in the code; the alternative interleaves the branch-switch decision with the per-file work, harder to read.

If perf measurements ever flag this, the optimization is one line.

## What changed for non-SCIP-covered files

Nothing. They take the existing `await this.indexFile(filePath)` path, which calls `storeExtractionResult(_, mode='replace')` and runs `deleteFile`. The sync rewrite is additive — SCIP coverage now triggers a different branch; absence of SCIP coverage stays the historical path.

## Risk callouts

- **`indexFileShadow` duplicates `indexFile`'s body** ~50 lines. Considered refactoring to share a private helper that takes the `mode` parameter; rejected because the read-file/stat path is a long sequence of error returns and inlining keeps the two methods independent. If we ever change the read path, we touch both.
- **The CLI warning fires once per sync** — if multiple branch switches happen in rapid succession (e.g. CI orchestration), the user sees a warning per sync invocation. Acceptable; refreshing once at the end is the intended UX.
- **No "you should refresh" prompt** — just a log line. UX is intentionally noisy-but-passive; agent integrations won't get blocked on a stdin prompt.
- **`logWarn` is the existing facility**; output formatting depends on its level filter. If `--silent` is passed, the warning is suppressed. Documented as a known edge case; users in CI environments may want to handle the staleness signal via `codegraph status` instead.
- **The shadow path runs THREE SQL operations per SCIP-covered file** (markScipFileStale, deleteFileTreeSitterRows, then tree-sitter inserts inside indexFileShadow). Each runs sync; total adds ~10ms per file vs the prior 1ms `indexFile`. For 50 SCIP-covered changed files, that's 500ms extra sync time — the threshold-bulk path kicks in at 51+ to keep this bounded.

## What the user sees now

**No SCIP coverage**: behavior unchanged. `codegraph sync` works exactly as before.

**SCIP coverage + small change set (≤ 50 SCIP files)**: shadow path runs per-file. SCIP rows are preserved (hidden), tree-sitter rows are fresh. Queries return tree-sitter data; status reports hidden-stale counts.

**SCIP coverage + large change set (> 50 SCIP files)**: bulk-mark runs once. CLI warns. Queries return SCIP data with `stale: true` annotation. User runs `codegraph scip-refresh` (P2.3) to restore precision.

**SCIP coverage + non-shadow-capable language file**: `markScipFileStale(F, 1)` — file shows up in queries as visible-stale, no fresh extraction.
