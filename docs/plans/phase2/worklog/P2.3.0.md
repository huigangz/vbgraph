## What's new

### Config

`CodeGraphConfig.scipRefreshCommand?: string` — default `'scip-dotnet index ./'`. Single command line, parsed via shell-style splitting at spawn time.

### CLI

`codegraph scip-refresh [path]` — single subcommand. Flow:

1. Resolve project root + open the project DB.
2. Acquire the `--scip-auto` lock file (shared lock semantics — refresh and auto-spawn must not race).
3. Spawn `config.scipRefreshCommand` with stdout/stderr captured to `.codegraph/logs/scip-refresh-<timestamp>.log`.
4. If exit code ≠ 0: write log path + exit code, exit 1.
5. Find the produced `.scip` file. **Default location**: `.codegraph/scip-cache/scip-refresh.scip` if the command's `--output` arg matches, else the working-dir convention `index.scip`. Configurable via `--scip-output <path>` CLI flag.
6. Call `ingestScipFile(scipPath, projectRoot, { db, qb, ... })`. Any throw → exit 2.
7. **Post-ingest assertion (NARROW, round 3 finding 1)**: for each file in the refreshed `scip_index_path`'s `scip_documents`, count `provenance = 'tree-sitter'` rows (EXACT match, NOT `LIKE 'tree-sitter%'`). Assert 0. Fallback rows (`'tree-sitter (scip-empty-fallback)'`) are LEGITIMATELY recreated by STAGE E and are NOT counted.
8. Update `.codegraph/scip-last-refresh.json` with `{ refreshedAt, scipPath, command, filesCovered, durationMs }`.
9. Exit 0.

### QueryBuilder additions

`countShadowRowsForFile(filePath)` — exact-match `provenance = 'tree-sitter'` count. Used by the post-ingest assertion.

### persister.ts

Broaden `supersedeTreeSitter` predicate from `provenance = 'tree-sitter'` to `provenance LIKE 'tree-sitter%'`. One-line change. Doesn't break existing tests because (a) the existing test corpus has zero shadow rows when ingesting (so the broader pattern matches nothing extra), and (b) the fallback re-creation at line 914 happens AFTER `supersedeTreeSitter`, so the new fallback rows still land.

## Exit-code contract

| Code | Meaning |
|---|---|
| 0 | Indexer succeeded AND ingest succeeded AND post-ingest assertion passed. |
| 1 | Indexer failed (non-zero exit OR crash OR missing output file). |
| 2 | Indexer succeeded but ingest threw (corrupt `.scip`, schema mismatch, post-ingest assertion failed). |

Matches the plan precisely.

## What's deliberately NOT in scope

- **Multi-indexer refresh**: `codegraph scip-refresh` runs one command. Users with multiple SCIP indexers (scip-dotnet + scip-typescript) should use `codegraph index --scip-auto` for the full sweep. P3 may add a `--scip-auto` flag to `scip-refresh` for parity.
- **Incremental refresh** (only re-ingest changed files): out of scope. STAGE B handles full re-ingest correctly and idempotently.
- **CI artifact ingest**: `codegraph index --scip <path>` already covers pre-built artifacts. `scip-refresh` is the "spawn-and-ingest" convenience path.
- **`scip-refresh.json` schema versioning**: the file is a status sidecar, not a contract. Schema evolution: add fields, never remove. P3 if it grows.

## Risk callouts

- **`scipRefreshCommand` parsing**: must shell-split safely. Existing convention in `auto-spawn.ts` is to spawn with `[cmd, ...args]` — I'll use the same parser (basic whitespace split with quoted-arg awareness). If a user has spaces in paths, they need to set `scipRefreshCommand` via the JSON config (where it can be an array).
- **Lock contention**: `scip-refresh` and `index --scip-auto` share the lock. If a user runs both, the second blocks. Acceptable behavior — concurrent SCIP writes would corrupt the DB.
- **Indexer output location convention**: `scip-dotnet` writes to `./index.scip` by default. Our convention is `.codegraph/scip-cache/`. Need to either (a) override the indexer's output via its CLI args, or (b) accept the default location. P2.3 defaults to `--scip-output ./index.scip` for the file location convention; user can override via the new CLI flag.
- **Post-ingest assertion runs SQL per refreshed file**: O(N) where N = SCIP-covered files. On a 10k-file repo, that's 10k SELECT COUNT(*) calls. Optimization: batch into one query with GROUP BY. Defer unless it's measurably slow.

## Open question (resolved)

**Should `scip-refresh` clear stale flags for files NOT covered by the refresh?** No — staleness was set per-file by sync. Re-ingest of THIS index clears its files' stale state implicitly via STAGE B's scope-delete + re-insert (the new rows write `stale=0, staleness_visible=0` per P2.1.4's freshness invariant). Files not covered by THIS refresh keep their stale flags until another sync or refresh touches them.
