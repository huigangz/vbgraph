# P0.0 — Toolchain detection + `--scip-auto` — Work Log

**Status:** Done (detection + lock delivered; `--scip-auto` spawn loop deferred to P0.6 by design).
**Date:** 2026-05-20

## Scope delivered

P0.0 in the plan has three parts: **detection**, **CLI surface**, **spawn orchestration**.
Detection is fully self-contained and is delivered here. The CLI surface (P0.7) and the
spawn-and-ingest loop depend on artifacts that do not exist yet (the P0.5 ingester, the
P0.4c failure ledger), so the *runtime wiring* of `--scip-auto` lands in P0.6 — its natural
home, which the plan itself labels "Auto-spawn for detected indexers (P0.0)". The two
standalone, independently-testable building blocks are delivered now.

### New files

- `src/extraction/scip/detect-indexers.ts`
  - `SCIP_INDEXERS` — the 7 known indexers (scip-dotnet, scip-java, scip-typescript,
    scip-python, scip-go, scip-rust, scip-ruby) with `cmd`, `languages`, `installHint`.
  - `detectInstalledScipIndexers({ force? })` — probes PATH via the `which` package,
    version-probes each hit with a 2 s `execFile` budget, caches per process.
    Invariant honored: a detected indexer is **never** excluded over a failed/unparseable
    version probe — version is informational only (`'unknown'` on any failure).
  - `clearScipIndexerDetectionCache()` — test seam for resetting the per-process cache.
  - `buildScipCoverageMap()` — `language -> indexer` map (first-declared wins on overlap).
  - `formatUninstalledIndexerHints()` — renders the post-Tier-0 install hints, optionally
    narrowed to the languages actually present in the repo.
- `src/extraction/scip/scip-auto-lock.ts`
  - `acquireScipAutoLock(codegraphDir)` — advisory `.codegraph/.scip-auto.lock` (PID +
    timestamp). Reclaims a stale lock (dead PID / corrupt file); throws `ScipAutoLockError`
    when a *live* foreign process holds it. Release runs on normal call and on
    SIGINT/SIGTERM, and only removes the file if still owned by this PID.
- `__tests__/p00-toolchain-detection.test.ts` — 13 tests (`which` mocked):
  detection subset / empty / full, version-probe-never-excludes, per-process caching +
  `force`, coverage map, hint formatting + repo-language narrowing, lock create/release,
  idempotent release, stale-PID reclaim, corrupt-file reclaim, live-foreign-PID rejection
  (uses a real spawned child for a genuine live PID).

### Dependencies added

- `which@^4.0.0` (runtime) — cross-platform PATH lookup, per the plan's mandate to avoid
  brittle raw `child_process.exec('which X')`. v4 chosen for CommonJS compatibility
  (`module: commonjs`); v5 is ESM-only.
- `@types/which` (dev).

## Deviation / forward-pull from P0.8

`detect-indexers.ts`'s spec'd `ScipIndexerSpec.languages: Language[]` references `'vbnet'`,
which forced the `Language` union to gain `vbnet` early. To keep the build green, the
following P0.8-attributed foundation was pulled forward:

- `src/types.ts` — `LANGUAGES` gains `'vbnet'` and `'external'`.
- `src/extraction/grammars.ts` — `GrammarLanguage` `Exclude<>` now also excludes
  `'external'`; `WASM_GRAMMAR_FILES` gains `vbnet: 'vbnet.wasm'` (the file itself arrives
  in P0.6b); `getLanguageDisplayName`'s `Record<Language,string>` gains `vbnet` / `external`.

The remaining P0.8 items (NODE_KINDS `constructor`/`event`, `EXTENSION_MAP['.vb']`, config
fields, `Node`/`Edge` field extensions, QueryBuilder touch points) stay with the P0.8
sub-phase.

## Environment note (pre-existing, not introduced here)

`better-sqlite3` native does not install on this machine (Node 24 ABI / no MSVC build
tools); the slow `node-sqlite3-wasm` fallback is active. Consequences for later phases:

- `foundation.test.ts > optimize` fails with `cannot VACUUM - SQL statements in progress`
  — a WASM-backend quirk, unrelated to SCIP work.
- Running the **full** suite in parallel workers OOMs (Node 24 + WASM SQLite memory).
  Workaround for verification: run targeted files, `--pool=forks`, one or few files at a
  time. This was confirmed pre-existing (the failure reproduces with only `types.ts`/
  `grammars.ts` enum additions, which cannot cause an OOM or a VACUUM error).
