### `src/index.ts` — `CodeGraph`

```ts
async refreshScip(options?: ScipRefreshOptions): Promise<ScipRefreshResult>;
```

Serialized by **both** the in-process `indexMutex` and the cross-process `FileLock` (`.codegraph/codegraph.lock`); the FileLock was added in review-round-4. A second concurrent process returns `phase = 'lock-failed'` without touching the database.

Steps (as actually shipped after review rounds 1–5):
1. Acquire `FileLock` — on contention, return `phase: 'lock-failed'`.
2. Spawn the configured indexer; capture stdout/stderr to `.codegraph/logs/scip-refresh-<ts>.log`. The log-stream error listener is attached synchronously so an unwritable log path returns `phase: 'spawn-failed'` instead of crashing the parent.
3. Pre-scan the produced `.scip` for languages, build the empty-doc fallback callback, then ingest via `ingestScipFile` (STAGE B/E).
4. Wholesale `invalidatePhase3Caches()` so post-ingest reads can't be served stale-cached rows from before the STAGE B raw DELETE.
5. Narrow post-ingest assertion: exact-match `provenance = 'tree-sitter'` rows must be 0 per refreshed file (fallback rows excluded by design).
6. Rerun resolution (when there are unresolved refs) and Phase 3 framework synthesis so derived data stays consistent. Recoverable Phase 3 per-resolver errors are appended to `derivedErrors` and persisted via three channels (stderr-bound CLI warning, per-run log file append, sidecar `lastError`) without demoting `phase` from `'ok'`.
7. Write `.codegraph/scip-last-refresh.json` (six fields: `refreshedAt`, `scipPath`, `command`, `filesCovered`, `durationMs`, `lastError`).

### `src/bin/codegraph.ts` — CLI

```
codegraph scip-refresh [path] [--cmd <command>] [--scip-output <path>] [-q|--quiet]
```

Maps `phase` to exit code: `'ok'` → 0, `'spawn-failed'` → 1, `'lock-failed'` → 1, `'ingest-failed'` → 2 (covers post-ingest assertion failure too).

## Refresh lifecycle (as shipped — updated through review round 5)

```
codegraph scip-refresh
       │
       ▼
indexMutex.withLock(async () => {
  fileLock.acquire()                              ← added review round 4
       │
       ├─ contended  →  return phase: 'lock-failed', exit 1
       │
       ▼
  createWriteStream(log) + sync 'error' listener  ← review round 5 (fix #1)
       │
       ├─ log open / write fails  →  return phase: 'spawn-failed', exit 1
       │     (no parent-process crash)
       │
       ▼
  spawn(cmd)  →  pipes stdout/stderr to log
       │
       ├─ exit != 0  →  return phase: 'spawn-failed', exit 1
       │
       ▼
  fs.existsSync(scipPath)
       │
       ├─ missing  →  return phase: 'spawn-failed', exit 1
       │
       ▼
  pre-scan languages + build extractFallback      ← added review round 1 (fix #1)
       │
       ▼
  ingestScipFile(scipPath, projectRoot, { db, qb, extractFallback })
       │   (STAGE B scoped delete + STAGE E supersedeTreeSitter LIKE 'tree-sitter%')
       │
       ├─ throws  →  return phase: 'ingest-failed', exit 2
       │
       ▼
  queries.invalidatePhase3Caches()                ← added review round 1 (fix #2)
       │
       ▼
  for file in getScipDocumentsForIndex(scipPath):
    if countShadowRowsForFile(file) > 0:  →  return phase: 'ingest-failed', exit 2
       │
       ▼
  if unresolved refs > 0: resolveReferencesBatched()    ← added review round 1 (fix #3)
       │
       ▼
  new Phase3Orchestrator(...).run()                    ← added review round 1 (fix #3)
       │   (per-resolver errors collected in result.errors per round 2)
       │
       ▼
  if derivedErrors:                               ← added review round 3
    appendFileSync(logPath, derived warning)          (after stream-finish; round 4)
       │   (per-channel persistence: stderr in CLI, log append here,
       │    sidecar lastError below — defense-in-depth for scheduled refresh)
       │
       ▼
  writeFile('.codegraph/scip-last-refresh.json', {
    refreshedAt, scipPath, command, filesCovered, durationMs,
    lastError                                     ← added review round 3
  })
       │
       ▼
  return phase: 'ok', exit 0
       │   (result.error is populated when derivedErrors was non-empty;
       │    CLI prints warning to stderr even under --quiet)
})
   ↑
fileLock.release()  ← finally block, always runs
```

## Risk callouts (consolidated)

- **Cross-process concurrency** — `refreshScip` initially used `indexMutex` (in-process only). **Updated 2026-05-25 (post-ship review round 4)**: `refreshScip` now acquires the cross-process `FileLock` in addition to `indexMutex`, matching the pattern in `indexAll` / `sync`. A second concurrent process exits with the new `'lock-failed'` phase (CLI exit code 1, `ScipRefreshResult.phase = 'lock-failed'`). `FileLock`'s acquire-side staleness check now treats live PIDs as authoritative regardless of lock-file age — previously a 2-minute mtime threshold could let a second writer in mid-refresh on large solutions. See [src/index.ts:949](../../../src/index.ts) and [src/utils.ts:194](../../../src/utils.ts).
- **Shell command tokenization** — single-string `scipRefreshCommand` originally split on `\s+`, mis-tokenizing paths with spaces. **Updated 2026-05-25**: now uses a quote-respecting `tokenizeShellCommand` helper. Double + single quotes group tokens; `\"` and `\\` escape inside double quotes. Array form still bypasses tokenization entirely.
- **Log file accumulation** — every refresh writes a timestamped log. No rotation. Documented as known issue, manual cleanup acceptable.
- **Sidecar write failure** — silent. Status command should treat missing sidecar as "never refreshed".
- **Assertion runs O(N) SELECTs** — fine for typical sizes; batch optimization deferred if perf demands.
