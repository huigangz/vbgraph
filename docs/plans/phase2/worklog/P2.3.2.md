# P2.3.2 — `countShadowRowsForFile` + `getScipDocumentsForIndex` helpers

**Status**: complete
**Date**: 2026-05-24
**Decisions**: design doc Decision 1 / round 3 finding 1 — assertion is NARROW (`provenance = 'tree-sitter'` only, NOT `LIKE 'tree-sitter%'`).

## Changes (`src/db/queries.ts`)

### `QueryBuilder.countShadowRowsForFile(filePath)`

```sql
SELECT COUNT(*) AS n FROM nodes WHERE file_path = ? AND provenance = 'tree-sitter'
```

Exact-match predicate, not `LIKE 'tree-sitter%'`. The narrow scope is intentional:

| Provenance | Counted? | Why |
|---|---|---|
| `'tree-sitter'` | YES | Sync's shadow output — the thing scip-refresh is meant to purge. |
| `'tree-sitter (scip-empty-fallback)'` | NO | Legitimately re-created by STAGE E's `maybeEmptyFallback` for empty SCIP docs. Counting these would fail the assertion on every empty doc. |
| `'scip'` / `'scip:external'` | NO | Not in the predicate. |

P2.3.3's post-ingest assertion calls this per refreshed file and asserts the count is 0.

### `QueryBuilder.getScipDocumentsForIndex(scipIndexPath)`

```sql
SELECT source_file_path FROM scip_documents WHERE scip_index_path = ?
```

Returns the list of source files covered by a `.scip` index. Drives the per-file assertion loop in P2.3.3.

### Prepared-statement cache

Added `countShadowRowsForFile` slot. `getScipDocumentsForIndex` not cached — typically called once per refresh (cardinality 1 prepared statement * 1 caller = no benefit from the slot).

## CI bypass guard impact

Both new SELECT sites would normally trigger the guard since they read `nodes` / `scip_documents` without `freshPredicate`. Both are LEGITIMATELY raw:

- `countShadowRowsForFile` IS the freshness-check function — applying `freshPredicate` would defeat its purpose (the assertion looks at raw column state to verify the cleanup worked).
- `getScipDocumentsForIndex` reads `scip_documents`, which has no staleness columns.

Added two entries to `NODE_ALLOWLIST` in `__tests__/p21-no-bypass.test.ts`. Markers are the literal SQL prefixes (unique within `queries.ts`).

CI guard now passes: 3/3.

## What this enables

P2.3.3's assertion loop:

```ts
const filesCovered = qb.getScipDocumentsForIndex(scipPath);
for (const filePath of filesCovered) {
  const shadowCount = qb.countShadowRowsForFile(filePath);
  if (shadowCount !== 0) {
    throw new Error(`scip-refresh leaked ${shadowCount} shadow nodes for ${filePath}`);
  }
}
```

If `supersedeTreeSitter` regresses (e.g., predicate narrows back to exact-match and a fallback row sneaks through to shadow-row count), this assertion fires.

## Risk callouts

- **Per-file COUNT(*) is O(N)** where N = SCIP-covered files. On a 10k-file project, that's 10k SELECT calls. Each is index-hit-then-COUNT — fast (sub-ms). Total ≤ 10s for the largest realistic refresh. Acceptable; can be batched into one GROUP BY if perf becomes an issue.
- **The assertion runs SEQUENTIALLY** in P2.3.3's loop — no batching. Trade-off: each failure surfaces the exact file path that leaked, which matters for diagnostics. A batched assertion would say "5 files leaked" without names.
