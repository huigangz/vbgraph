### 2. Persister fix — real `scip-dotnet` output broke containment

Ingesting the *real* `.scip` surfaced a P0.4 defect that the synthetic fixtures
masked. The synthetic fixtures use idealised body-spanning definition ranges;
`scip-dotnet` 0.2.14 emits **name-token-only** definition ranges and an empty
`enclosing_range`. The persister derived containment and call-site enclosure
purely from positional range nesting, so against real output:

- `contains` collapsed to **flat** — the file node contained every symbol; no
  `Class → Method` nesting.
- every `calls` / `references` edge **source** collapsed to the file node
  (`Catalog.vb → TotalArea` instead of `Summary → TotalArea`).
- method-implementation relationships emitted bogus `extends` edges between two
  `method` nodes.

This meant P0 ship gate 4 ("a complete .NET project graph with cross-file
edges") did not actually hold against real indexer output. Fix, in
`src/extraction/scip/persister.ts`:

- **Containment from the SCIP symbol descriptor path.** `A#foo().` is
  structurally contained by `A#`, `A#foo().(p)` by `A#foo().` — SCIP encodes
  this in the symbol string itself, independent of source ranges. Positional
  `enclosingDefinition` remains the fallback for indexers that *do* emit
  body-spanning ranges (the synthetic fixtures), so all 13 synthetic tests stay
  green.
- **Call-site enclosure fallback.** When positional enclosure finds nothing,
  attribute a reference to the nearest preceding scope definition by start
  position.
- **`overrides` edge kind.** A method/property `isImplementation` relationship
  is now an `overrides` edge; type→interface is `implements`, type→class is
  `extends`.

The result is a proper graph: `ShapeCatalog contains Summary`,
`Summary calls TotalArea` (×2, distinct lines, sourced from the method),
`Shape.Area overrides IShape.Area`, `Rectangle extends Shape`.

## Findings from the real `scip-dotnet` 0.2.14 output

These are indexer-side limitations the validation surfaced. They are *not*
persister bugs — they are recorded here the way P0.6b recorded the VB grammar
gaps.

1. **`SymbolInformation.kind` is always `0`.** The ingester falls back to the
   descriptor suffix, so the `#` suffix maps every VB type to `class`. VB
   `Module` does **not** surface as `kind='module'`, and `Interface` does not
   surface as `kind='interface'` — which in turn means VB `Implements` produces
   `extends` rather than `implements` (the persister can only emit `implements`
   when the target node is `kind='interface'`). VB `Property` (`.`/term
   descriptor) surfaces as `variable`. A newer `scip-dotnet` that populates
   `kind` would fix all of these with no CodeGraph change.
2. **No `external_symbols`.** BCL references (`System.Console.WriteLine`,
   `List(Of T).Add`, …) appear as occurrences whose symbol is defined nowhere in
   the index and is absent from `external_symbols`, so they land in
   `stats.unresolvedCount` rather than becoming `scip:external` nodes. The
   external-node shape is therefore still covered only by the synthetic
   fixtures in `scip-ingester.test.ts`.
3. **Name-only definition ranges / empty `enclosing_range`** — handled by the
   persister fix above.

## Memory benchmark — deferred, with reason

P0.10 calls for a synthetic 500 MB `.scip` (~1M definitions) ingesting with an
RSS delta < 200 MB. This is **not promotable as a routine test in the current
environment**:

- The environment has no native `better-sqlite3`; the active backend is
  `node-sqlite3-wasm`, which holds the **entire database in WASM linear
  memory**. Ingester RSS therefore scales with database size — a fixed RSS
  budget would measure the backend, not the persister's working set.
- A 500 MB ingest is ~9 minutes under the WASM backend (measured: 41 s to
  ingest a 39 MB / 20k-document synthetic index).

The genuine memory red-line — the **streaming decoder** (P0.1) — is already
proven by `p01-streaming-decoder.test.ts`: an 80 MB `.scip` iterates with an RSS
delta < 64 MB. The persister wraps that same streaming decoder and batches 50
documents at a time, so it adds no whole-index buffering. The 500 MB *ingester*
benchmark should be promoted once `better-sqlite3` (native, on-disk paged) is
the active backend, where RSS reflects the persister's bounded working set.
