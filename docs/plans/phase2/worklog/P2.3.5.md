## What the round-trip test proves

The most load-bearing test is "STAGE E maybeEmptyFallback re-creates fresh fallback rows after supersede" — this is the round 3 finding 1 fix in action:

1. Seed an `'old-fb'` fallback row in the DB.
2. Set up a synthetic `.scip` with one empty SCIP doc + a real file on disk > 200 bytes (the default `emptyFallbackThresholdBytes`).
3. Provide an `extractFallback` callback that emits a `'fresh-fb'` node.
4. Run `persistScipIndex` — which calls `supersedeTreeSitter` (widened in P2.3.1) followed by `maybeEmptyFallback`.
5. Assert: `'old-fb'` is GONE (wiped by supersede), `'fresh-fb'` is PRESENT (created by maybeEmptyFallback).

If the widening regressed back to exact `provenance = 'tree-sitter'`, `'old-fb'` would survive and the test fails.
If `maybeEmptyFallback` ran BEFORE supersede, `'fresh-fb'` would be wiped by supersede and the test fails.

The current ordering is correct (supersede then fallback creation), proven by this test.

## What's NOT covered here

- **End-to-end `cg.refreshScip()` flow** — would require spawning a real `scip-dotnet` subprocess. Out of scope; covered by manual smoke when integrating the CLI.
- **Sidecar JSON output** — file-format coverage. The CLI writes it via `JSON.stringify`; nothing complex enough to warrant a unit test.
- **Spawn failure modes** (non-zero exit, crash, missing output) — covered by inspection in P2.3.3's worklog; explicit tests would need an env-specific subprocess setup. Manual verification: invoke `codegraph scip-refresh` with a missing `scip-dotnet` binary → exit 1.

## Failure modes the suite would catch

1. **Reverting `supersedeTreeSitter` to exact match** → "re-ingest clears both tree-sitter AND fallback rows" fails (old fallback survives).
2. **Mistakenly widening `countShadowRowsForFile` predicate** → "the assertion is narrow" fails (fallback counts as leak).
3. **Reordering supersede + maybeEmptyFallback** → "STAGE E maybeEmptyFallback re-creates" fails (fresh fallback gets wiped).
4. **`getScipDocumentsForIndex` filtering wrong column** → returns files from other indexes too.
