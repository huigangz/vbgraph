### `src/index.ts` — `CodeGraph.refreshScip(options?)`

Public async method, serialized by **both** the in-process `indexMutex`
(that guards `indexAll` / `sync`) **and** the cross-process `FileLock`
(`.codegraph/codegraph.lock`) added in review-round-4. Concurrent refresh /
index / sync calls in the same process queue on the mutex; concurrent
refresh from a second process returns `phase = 'lock-failed'` without
touching the database.

Flow as shipped (final — covers all subsequent review rounds):

1. **Acquire `FileLock`** (round 4). Contention → return `phase: 'lock-failed'`.
2. **Create the per-run log stream** via the private `createRefreshLogStream` indirection so failure paths are testable. Attach the `'error'` listener synchronously (round 5) so an EACCES/EROFS/EISDIR on open is captured into `logStreamError` instead of crashing the parent.
3. **Spawn** the indexer (`options.command` || `config.scipRefreshCommand` || default `'scip-dotnet index ./'`). Capture stdout/stderr to the log stream. Tokenize a single-string command via the quote-respecting `tokenizeShellCommand` helper (round 4) OR accept a pre-tokenized array (P2.3.4 config field type union).
4. **Inspect `logStreamError`** (round 5 — open-failure path). If set, return `phase: 'spawn-failed'` with the captured cause.
5. **Check spawn exit code**: non-zero or process error → return `phase: 'spawn-failed'`.
6. **Wait for `logStream` finish** (round 4), then **re-inspect `logStreamError`** (round 6 — flush-time path). If a write or final flush error fired during the drain, return `phase: 'spawn-failed'`.
7. **Locate output `.scip`** at `options.scipOutputPath` || `config.scipRefreshOutputPath` || `./index.scip`, resolved relative to project root. Missing file → `'spawn-failed'`.
8. **Pre-scan covered languages and build `extractFallback`** (round 1) so the persister's empty-document fallback can be recreated for SCIP docs with zero occurrences.
9. **Ingest** via existing `ingestScipFile(scipPath, projectRoot, { db, qb, extractFallback })`. Any throw → `'ingest-failed'`.
10. **Wholesale `invalidatePhase3Caches()`** (round 1) so the QueryBuilder's node cache cannot serve pre-refresh entries after STAGE B's raw DELETE.
11. **Post-ingest assertion (NARROW)**: enumerate files via `getScipDocumentsForIndex(scipPath)`; for each, `countShadowRowsForFile(file)` must be 0 (exact-match `provenance = 'tree-sitter'` only — fallback rows are legitimately re-created). If any non-zero, return `'ingest-failed'` with up to 5 file names in the error message.
12. **Rerun resolution + Phase 3 framework synthesis** (round 1) so framework tags and scope-resolved edges stay consistent with the refreshed SCIP graph. Recoverable per-resolver errors (`phase3Result.errors`, round 2) are captured into `derivedErrors` rather than throwing.
13. **Persist any derived errors** (round 3) across THREE channels: append `[codegraph derived-data warning <iso>]` to the per-run log file (after the stream-finish wait so ordering is stable per round 4), emit to stderr via the CLI's `process.stderr.write`, and write the sidecar `lastError` field.
14. **Write status sidecar** at `.codegraph/scip-last-refresh.json` with six fields (`refreshedAt`, `scipPath`, `command`, `filesCovered`, `durationMs`, `lastError`). Best-effort — sidecar write failure does not affect return phase.
15. **Return** `{ phase: 'ok', error: <derivedErrors-joined or null>, ... }`. `FileLock` releases in the `finally`.

### `src/bin/codegraph.ts` — `program.command('scip-refresh [path]')`

Thin CLI wrapper:

- Resolves project path; errors if not initialized.
- Opens CodeGraph; calls `cg.refreshScip({ command, scipOutputPath })`.
- Maps `result.phase` to exit code (0 / 1 / 2 per the design's contract).
- On non-`ok`, surfaces the error + log path + spawn exit code via `error()` / `info()`.

CLI sanity-checked:

```
$ codegraph scip-refresh --help
Usage: codegraph scip-refresh [options] [path]
Re-run the configured SCIP indexer and ingest its output
Options:
  --cmd <command>       Override `config.scipRefreshCommand`
  --scip-output <path>  Override `config.scipRefreshOutputPath`
  -q, --quiet           Suppress non-error output
```

## Sidecar schema

`.codegraph/scip-last-refresh.json`:

```json
{
  "refreshedAt": "2026-05-24T09:21:33.000Z",
  "scipPath": "/abs/path/to/index.scip",
  "command": "scip-dotnet index ./",
  "filesCovered": 1234,
  "durationMs": 5678
}
```

Schema is informal — fields can be added (never removed) without versioning. Consumers: `codegraph status` (P2.4) reads this for the "last refresh time" line; humans inspect it directly.

## Why the spawn is direct, not via runScipAutoSpawn

- `runScipAutoSpawn` detects ALL installed indexers and runs each. `scip-refresh` runs the single user-configured command. Different semantics; sharing the spawn primitive would be premature abstraction.
- `runScipAutoSpawn` acquires `.scip-auto.lock`. `scip-refresh` originally used `indexMutex` only — **updated 2026-05-25 (post-ship review round 4)**: now also acquires the cross-process `FileLock` (`.codegraph/codegraph.lock`), matching `indexAll` / `sync`. See the Risk callouts section below for the full contract.

## Risk callouts

- **Cross-process concurrency**: ~~two `scip-refresh` calls from separate processes will both acquire the `indexMutex` (in-process only) and race on file-system operations.~~ **Updated 2026-05-25 (post-ship review round 4)**: `refreshScip` now also acquires the cross-process `FileLock` (`.codegraph/codegraph.lock`), matching `indexAll` / `sync`. A second concurrent invocation returns the new `'lock-failed'` phase (exit code 1) without touching the database. `FileLock`'s liveness check now treats a live PID as authoritative; the previous 2-minute mtime override that could free the lock under a long-running refresh has been removed. See [src/index.ts](../../../src/index.ts) and [src/utils.ts](../../../src/utils.ts).
- **Log file accumulation**: every refresh produces a timestamped log. After N refreshes, `.codegraph/logs/` grows linearly. Existing `runScipAutoSpawn` has the same pattern — log rotation is out of scope. Users can clean manually.
- **Log-file write ordering**: `refreshScip` pipes the child's stdout/stderr into the per-run log via a write stream, then may `appendFileSync` a derived-data warning to the same file. **Updated 2026-05-25 (round 4)**: the implementation now awaits the stream's `finish` event before the append so child output and the warning are not interleaved. Regression coverage: [p2-review-fixes.test.ts](../../../__tests__/p2-review-fixes.test.ts) "preserves indexer-output / derived-warning ordering with a noisy child".
- **Sidecar write failure is silent** — if `.codegraph/` is read-only or the disk fills, `refreshScip` still returns `'ok'` but the sidecar is missing. Status command should treat missing sidecar as "never refreshed", not error.
- **Shell-splitting `command` via whitespace** originally mis-tokenized paths containing spaces. **Updated 2026-05-25 (round 4)**: now uses a quote-respecting tokenizer; CLI `--cmd` strings can wrap a spaces-containing executable path in double or single quotes. Array form in the config still bypasses tokenization entirely.
- **The mutex blocks `sync`/`indexAll` during refresh**. A long refresh (minutes for large projects) holds the lock. Acceptable: refresh is rare, run-once-per-cron-tick; concurrent ops should wait.
