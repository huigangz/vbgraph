# P2.4.1 — Expose `getStaleSummary` + `getStatsIncludingStale` on `CodeGraph`

**Status**: complete
**Date**: 2026-05-24
**Decisions**: design Decision 5 (three-surface model) — surfaces must reach the public API for `codegraph status` (P2.4.4) and future programmatic consumers.

## Changes (`src/index.ts`)

Two new public methods on `CodeGraph`, both thin delegates to `QueryBuilder`:

```ts
getStatsIncludingStale(): GraphStats;
getStaleSummary(): StaleSummary;
```

JSDoc on `getStats()` updated to cross-reference the new methods and the design decision.

`StaleSummary` added to the type imports from `./types`.

## Why two methods, not one

The three surfaces (filtered stats, raw stats, decomposed breakdown) serve distinct callers:

- **`getStats()`** — agent-facing default. Excludes hidden-stale to match query semantics.
- **`getStatsIncludingStale()`** — raw escape hatch. Status diagnostics + parity.
- **`getStaleSummary()`** — decomposed counts. Status sections that distinguish "shadow active" from "needs refresh".

Wrapping all three in one method would force every caller to know about all three categories — premature consolidation.

## `dbSizeBytes` set on both

`getStats()` sets `stats.dbSizeBytes = this.db.getSize()` after the QueryBuilder call. `getStatsIncludingStale()` does the same — the raw totals object also needs the live DB-size value (QueryBuilder doesn't know about the connection's size getter).

## Validation

- `npx tsc --noEmit` clean.
- No behavioral test yet (just delegation); P2.4.6 covers the wider status output.

## Risk callouts

- **`getStatsIncludingStale()` and `getStats()` share the dbSizeBytes set pattern** — if the field ever moves to QueryBuilder, update both call sites.
- **`StaleSummary` import position** — added at the end of the import block; alphabetical convention is not followed elsewhere in the file, so existing order kept.
