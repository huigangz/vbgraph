## What the most load-bearing tests catch

### #5 — freshness invariant on shared-fingerprint edges

```ts
qb.upsertGraphEdge({source:'A', target:'B', line:10, provenance:'scip'});
qb.markScipFileStale('A.cs', 0);
// edge now stale=1

qb.upsertGraphEdge({source:'A', target:'B', line:10, provenance:'tree-sitter'});
// MUST: row stale=0, primary='scip', provenances=['scip','tree-sitter']
```

If `upsertGraphEdge`'s UPDATE branch ever dropped the `stale=0, staleness_visible=0` reset, P2.2's shadow-sync loop would deadlock — sync inserts tree-sitter shadow at the SCIP edge's fingerprint, but the merged row stays hidden because stale never clears. This test catches the regression.

### #11 — Decision 7 endpoint visibility

The most user-visible Decision 7 contract: hide a node, all incident edges disappear from public queries. Multiple variants ensure both directions (incoming + outgoing) AND `findEdgesBetweenNodes` honor the rule. Without this, dangling edges leak through.

The visible-stale variant (case c) is the dual: visibility-coherent does NOT mean "stale=anything hides the edge" — only `stale=1 AND staleness_visible=0` (hidden-stale) hides. Visible-stale (`stale=1 AND staleness_visible=1`) passes the default filter.

## Test architecture

Single file, ~13 tests, ~250 lines. All use the QueryBuilder-direct setup (no CodeGraph instance) — `DatabaseConnection.initialize(getDatabasePath(projectRoot))` + `new QueryBuilder(db)`. Each test gets a fresh DB via `beforeEach`.

Raw-row helpers (`readRawNode`, `readRawEdge`) bypass `rowToNode`/`rowToEdge` so tests can assert on the underlying SQLite integer columns directly — necessary to distinguish hidden-stale (0) from visible-stale (1) from fresh (NULL/0).

## Failure modes the suite catches

1. **Removing `stale=0, staleness_visible=0` from `insertNode`** → "insertNode writes stale=0" fails.
2. **Removing the `stale=0` reset in `upsertGraphEdge` UPDATE branch** → "pre-stale SCIP edge + tree-sitter upsert" fails (the freshness invariant).
3. **Reverting `getStats` to raw counts (P2.1.7 regression)** → "hidden-stale excluded from getStats" fails.
4. **Removing `visibleNodeIdPredicate` from any of the 4 public edge queries** → respective Decision 7 test fails.
5. **`getAllNodeNames` reverting to no `freshPredicate`** → "getAllNodeNames omits names from hidden-stale rows" fails.
6. **Mistakenly hiding visible-stale rows from public queries** → "visible-stale names ARE returned" fails (a tricky regression because the obvious "filter all stale" instinct breaks this).

## Risk callouts

- **No tests for `*IncludingDanglingEndpoints` siblings** — none exist yet (deferred per P2.1.6 worklog). When a sibling lands, add a paired test that asserts the sibling DOES surface what the default filters out.
- **`findEdgesBetweenNodes` test uses 3 nodes / 2 edges** — minimal but representative. Bigger graphs untested; perf-side coverage is in P2.6.1.
- **No test combines source-only edge stale (Decision 2) with endpoint visibility (Decision 7)** — they interact in the design's "stale persistence" scenario which is covered separately by #6. A combined test would be redundant.
