# P2.4.3 — Per-language tier detection

**Status**: complete
**Date**: 2026-05-24
**Decisions**: design § P2.4 — status reports per-language tier ("C#: Tier 1 SCIP (scip-dotnet 0.4.2); VB.NET: Tier 0 tree-sitter").

## Changes

### `src/types.ts` — `LanguageTier` interface

```ts
interface LanguageTier {
  language: Language;
  filesInRepo: number;
  tier: 'tier-0' | 'tier-1';
  scipNodeCount: number;
  treeSitterNodeCount: number;
  scipIndexerAvailable: boolean;
  scipIndexerInstalled: string | null;
  installHint: string | null;
}
```

Documented: `tier-1` means at least one node with `provenance = 'scip'` exists in the DB for the language; `tier-0` means tree-sitter is the only source.

### `src/db/queries.ts` — `getNodeCountsByLanguageAndProvenance()`

```sql
SELECT language, provenance, COUNT(*) AS count
  FROM nodes
 GROUP BY language, provenance
```

Raw read (no `freshPredicate`) by design — hidden-stale SCIP rows still count as "Tier 1 coverage exists in DB". Added to `NODE_ALLOWLIST` in the CI bypass guard with reason.

One query instead of `N × 2` per-language COUNTs.

### `src/index.ts` — `CodeGraph.getLanguageTiers()`

Async (because `detectInstalledScipIndexers` is async).

Algorithm:
1. Read `stats.filesByLanguage` — the set of languages with files in the repo.
2. Fetch `getNodeCountsByLanguageAndProvenance` — group by (language, provenance).
3. Aggregate per-language: `scip` count and any `tree-sitter%` count (the `startsWith('tree-sitter')` check catches both regular and `scip-empty-fallback` variants).
4. `detectInstalledScipIndexers()` + `buildScipCoverageMap(detected)` to determine `scipIndexerAvailable` / `scipIndexerInstalled`.
5. For languages with NO installed indexer, look up `SCIP_INDEXERS` for any spec covering this language → `installHint`.
6. Sort by `filesInRepo` descending.

Imports added: `detectInstalledScipIndexers`, `buildScipCoverageMap`, `SCIP_INDEXERS` from `./extraction/scip`; `LanguageTier` from `./types`.

## Why "starts with 'tree-sitter'" catches both variants

The `'tree-sitter (scip-empty-fallback)'` provenance is **SCIP-coverage-with-empty-doc** — semantically Tier 1 with a tree-sitter assist. But for the per-language tier UI, the relevant signal is "do real SCIP nodes exist". Falling through to count it under `treeSitter` is correct — a file with only fallback rows is effectively syntactic-precision, not compiler-precision.

If a language has ONLY fallback rows (every SCIP doc was empty), `scip = 0` and `tier-0` is reported. Counter-intuitive at first glance, but matches user mental model ("did the indexer extract symbols, or did it punt?").

## Why detection is cached

`detectInstalledScipIndexers` probes the PATH for ~7 indexers, each with a 2s timeout. Without caching, every `getLanguageTiers()` call would re-probe. The existing in-process cache ([detect-indexers.ts:108](../../../src/extraction/scip/detect-indexers.ts#L108)) makes the second call free.

For a single `codegraph status` invocation: one probe round (~250ms), one DB query (~5ms). Acceptable.

## Risk callouts

- **`coverage.has(L)` is keyed by Language enum strings**, NOT free-form strings. If the DB has nodes with `language = 'unknown'` or a custom value, the coverage map lookup misses → `scipIndexerAvailable = false`. Acceptable: unknown languages don't have indexers anyway.
- **Sort by file count** can produce ties; secondary sort isn't defined. For status display, tied languages render in arbitrary order — fine.
- **Async method** — status command must `await` it. Current status command is already an async action handler; trivial to integrate in P2.4.4.
- **Detection requires `which` package + subprocess spawn** — already used by `--scip-auto`. P2.4 inherits the same dependency surface.
