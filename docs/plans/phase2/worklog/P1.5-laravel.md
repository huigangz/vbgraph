# P1.5 PR-10 — laravel migration (Facade resolution upgrade)

**Status**: complete
**Date**: 2026-05-23

## What landed

`src/resolution/frameworks/laravel.ts` rewritten with the plan's
"Facade resolution upgrades" augment.

- `detect` — unchanged.
- `extract` → `synthesize`:
  - `Route::METHOD('/x', handler)` — `route` node, ID prefix
    `framework:laravel:route:…`.
  - `Route::resource('name', X::class)` — `route` node with name
    `resource:<name>`, ID prefix `framework:laravel:resource:…`.
  - Both with `provenance='framework:laravel'`.
- `resolve` → `augment`:
  - **Route → handler convention edges**: parses the route's source line
    via `extractLaravelHandler` to recover one of:
    - `[Class::class, 'method']` → method name
    - `'Controller@method'` → method name
    - `Class::class` (resource shape) → class name
    Strict resolution: candidates filtered by kind (method/function for
    method-style, class for class-style), preferred-in-`/Controllers/`,
    single-match-only — same conservative precision used by aspnet/express.
    Emits `references/convention` (NULL line/col), plus
    `laravel:controller` + `route-handler` tags on the handler node.
  - **Facade resolution upgrade** (per plan's PR-10 main payoff):
    walks `FACADE_MAPPINGS`. For each facade name present as a class in
    the graph AND whose underlying-class short-name is also present,
    enumerates the facade's methods and emits a
    `references/convention` edge from every incoming `calls` edge's
    source to the underlying class. Tags the facade class as
    `laravel:facade`. Only fires when both classes are actually
    indexed — purely static, no runtime container introspection.
- `resolve` and `extract` fields removed.

## Notes

- The facade upgrade is gated on both classes being in the indexed
  graph. Most user projects won't have Illuminate vendor code indexed,
  so this path is mostly inactive in practice — but it's the
  cleanly-defined hook the plan calls for, ready for projects that DO
  vendor or stub.
- The legacy `resolveModelCall` / `resolveControllerMethod` paths were
  heuristic file-path conventions (`app/Models/<Name>.php`, etc.). They
  were dropped — the new augment's by-name resolution against the
  graph's actual nodes covers the same cases more precisely when the
  classes exist in the index. PHP doesn't have a scope resolver yet
  (P0.5b covers csharp/vbnet/java/python/typescript), so some recall is
  lost for projects that depend on the legacy heuristic — same trade-off
  documented in [P1.5-rails.md](P1.5-rails.md).
