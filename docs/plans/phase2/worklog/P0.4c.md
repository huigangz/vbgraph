## Scope delivered

### `src/extraction/scip/failure-ledger.ts`

- `ScipFailureMode` — the seven failure modes from the plan's table (`not-installed`,
  `startup-failed`, `restore-failed`, `build-failed`, `truncated`, `corrupt`,
  `version-mismatch`).
- `ScipFailure` / `ScipFailureLedger` types matching the documented JSON shape.
- `writeScipFailureLedger(codegraphDir, failures)` — **atomic** write (sibling `.tmp` +
  `renameSync`), overwriting any previous ledger; top-level `version: 1`.

  unknown schema version (`"scip-failures.json schema version <N> unknown"`).
- `classifyScipFailureMode(err)` — maps a thrown error / spawn outcome to a mode
  (`ENOENT` -> `not-installed`, "unexpected EOF" -> `truncated`, etc.). Used by the P0.6
  `--scip-auto` orchestrator to populate the ledger.

proves the one fatal case (gate 12a) already holds.

## The invariant

> No SCIP failure mode causes a fatal CodeGraph exit. The only fatal cases are an
> explicit `--scip <path>` with a corrupt file (caller-induced — gate 12a, verified here)
> or an unrecoverable internal bug.

Gate 12a holds because of the persister's STAGE A / STAGE B ordering. The auto-mode side
of the invariant (gate 12 — degrade and exit 0) is completed with the P0.6 orchestrator.
