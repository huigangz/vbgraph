## Test architecture

Two setup helpers because WASM SQLite doesn't allow concurrent connections:

- **`setupQueryBuilder()`** — opens DB directly. For the grouped-count tests that don't need a `CodeGraph` instance.
- **`setupForCodeGraph()`** — `CodeGraph.initSync` (sets up dirs + config + DB), `cg.close()`, then opens a fresh `QueryBuilder` connection for seeding. Returns `{ reopenCg }` — the test calls `reopenCg()` after seeding to close the QB connection and open a fresh `CodeGraph` instance.

This pattern eliminates "database is locked" errors from concurrent WASM connections while keeping test bodies linear.

## SCIP indexer-detection warmup

`detectInstalledScipIndexers()` probes the PATH for 7 binaries with 2s timeouts each. First call can take 5+ seconds on systems where most indexers are absent — exceeding vitest's default 5s test timeout.

The cache is module-level (per Node.js process), so warming it ONCE per suite via `beforeAll` (30s timeout) amortizes the cost. Without warmup, only the first `getLanguageTiers` test sees the timeout; with it, all tests run sub-3s.

## Failure modes the suite catches

1. **Sidecar shape regression** (a field renamed or dropped) → `getLastScipRefresh` parsing test fails.
2. **`getNodeCountsByLanguageAndProvenance` accidentally adds `freshPredicate`** → "reads RAW state" test detects hidden-stale rows getting filtered.
3. **Fallback inclusion regression** (counting `tree-sitter (scip-empty-fallback)` as scip) → "scip-empty-fallback toward treeSitterNodeCount" test fails.
4. **Sort ordering inverted** → "sorted by file count descending" fails.
5. **`getLanguageTiers` becomes synchronous** → all 5 tier tests fail at the type level.

## Risk callouts

- **Test relies on `CodeGraph.initSync` then close-and-reopen pattern** — added friction vs reading the QueryBuilder directly from `cg`. The CodeGraph class doesn't expose `queries` publicly, so test-only access requires either close/reopen or a test-only accessor. Picked close/reopen as the smaller API change.
- **SCIP indexer warmup takes 5+ seconds on cold processes**. In CI, this surfaces as one slow test suite. Acceptable for a status-specific suite.
- **No direct CLI text-output test** — the `codegraph status` text rendering is deterministic given the helper outputs. Adding a snapshot test on the text would couple to chalk color codes and terminal width; deferred until a real rendering regression motivates it.
- **No JSON shape snapshot test** — same rationale. The JSON shape is a transitive function of the helpers tested here; snapshot would add maintenance churn.
