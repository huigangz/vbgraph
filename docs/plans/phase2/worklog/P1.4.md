## What landed

### New file: `src/resolution/phase3.ts` (~320 lines)

- `class Phase3Orchestrator` — constructor `(projectRoot, queries)`.
  - Re-detects frameworks against a fresh DB-backed `ResolutionContext`
    built in `buildPostExtractionContext()`. This is the F2 fix: the
    constructor-time `ReferenceResolver.frameworks` field was built
    against an empty `getAllFiles()` and silently dropped any scan-based
    detect; Phase 3 must re-detect after extraction completes.
  - Stores the detected `FrameworkResolver[]` for use by `runSync`.
  - Caches file reads (`fileCache: Map<string, string | null>`) so the
    same file isn't re-read across the orchestrator's two views and the
    detect context.
- `Phase3Result` interface: `nodesAdded`, `edgesAdded`, `tagsAdded`,
  `errors`, `detectedFrameworks`.
- `run(onProgress?)` → `Promise<Phase3Result>` — public API. Internally
  delegates to `runSync` inside `queries.transaction(...)`. Returned as a
  Promise to match `indexAll` / `sync` callsite shape; nothing inside is
  actually awaitable (R3-F3, R5-F3).
- `runSync(onProgress?)`:
  - **STAGE 0** — purge first, before any read. Calls four QueryBuilder
    helpers in order, then `invalidatePhase3Caches()`. Unconditional
    (R3-F2 fix). Runs as the FIRST writes inside the transaction (R4-F1).
  - **view1** — `QueryGraphView` constructed AFTER purge so synthesize
    sees a clean static layer.
  - **STAGE A** — `synthesize` loop. Sequential, sync, per-resolver
    try/catch. Throws become one `phase3.synthesize.throw` warning;
    sibling resolvers complete normally.
  - **STAGE B** — node persistence then inherent-tag persistence.
    - `assertSynthesizedNode` rejects nodes with: unknown `kind`
      (not in `NODE_KINDS`), wrong `provenance` (must equal
      `framework:<name>`), id missing the namespaced prefix.
    - Node ID collisions across resolvers: first-occurrence wins; a
      `phase3.synthesize.id_collision` warning is logged for losers.
    - Uses `insertNode` (single-row) per node, NEVER `insertNodes`
      (which opens an inner tx and would fail on WASM, R5-F1, R6-F2).
    - Tag pre-flight per (nodeId, tag): `view1.hasNode || synthNodeIds`,
      `isValidTagFormat`, then `try/catch` around `insertNodeTag`.
      Bad inserts logged, never escape.
  - **STAGE C** — `view2 = QueryGraphView(...)`, constructed inside the
    transaction. Reads in-transaction writes (better-sqlite3 / WASM both
    honor transactional reads on the same connection).
  - **STAGE D** — `augment` loop. Same shape as STAGE A.
  - **STAGE E** — edge persistence then derived-tag persistence.
    - Edge pre-flight: `metadata` must be undefined/empty (R3-F4);
      provenance must equal `framework:<name>`;
      `validateEdgeLineColumn(edge)` enforces the three-tier invariant.
    - Tag pre-flight: same as STAGE B, but only `view2.hasNode` since
      view2 already sees synthesized nodes.
- `isValidTagFormat(tag)` — exported. Regex `/^[a-z0-9][a-z0-9-]*(?::[a-z0-9][a-z0-9-]*)*$/`,
  length 1–64.

### Wired into `src/index.ts`

- `indexAll` ([src/index.ts:710](src/index.ts#L710)): unconditional after
  `result.success`, OUTSIDE the resolution gate so tag-only and
  synthesize-only resolvers still run on projects with zero unresolved
  refs (F5).
- `sync` ([src/index.ts:792](src/index.ts#L792)): unconditional after the
  per-file resolution branch. `result.phase3` populated via the new
  optional `SyncResult.phase3` sub-object (F4).

### Test infrastructure notes

- `objectExists` helper made WASM-resilient
  (`row !== undefined && row !== null`) in PR-1 tests; reused via copy in
  the new file (`p1-phase3-orchestrator.test.ts` doesn't currently use
  it, but the pattern is established).
- Test #25's first attempt spied on `db.exec` to count BEGIN/COMMIT, but
  the WASM adapter's `transaction()` calls `this._db.exec('BEGIN')`
  directly (bypassing the adapter's own `exec`). Rewrote the test to
  spy on `q.transaction` AND `db.transaction` — both must be called
  exactly once. Captures the same invariant via a different lever.
- Fake resolvers register via `registerFrameworkResolver` in `beforeEach`
  and unregister in `afterEach` (via `unregisterFrameworkResolver`),
  cleaning up cross-test state in `FRAMEWORK_RESOLVERS`.

## Notes for follow-up

- The legacy `extract` hook still runs. As each resolver migrates in
