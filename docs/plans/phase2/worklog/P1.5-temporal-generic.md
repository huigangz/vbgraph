# P1.5 PR-15 — generic `temporal` resolver

**Status**: complete
**Date**: 2026-05-23

## What landed

### New file: `src/resolution/frameworks/temporal.ts`

Cross-language Temporal SDK dispatch resolver. Augment-only —
synthesize is no-op.

- `name: 'temporal'`, no `languages` (universal).
- `detect`:
  - **Only fires when Spring is NOT detected** (`!detectSpring(context)`)
    so spring-temporal owns the Java/Spring case without duplicate
    contributions. Java-without-Spring is correctly picked up by this
    resolver.
  - Positive signals: `@temporalio/client`/`workflow`/`worker` in
    package.json, `go.temporal.io/sdk` in go.mod, `temporalio` in
    requirements.txt or pyproject.toml.
- `augment` — for each indexed file in a supported language
  (.go / .ts / .tsx / .js / .jsx / .mjs / .cjs / .py / .java), scans
  via a language-specific regex:
  - **Go**: `client.ExecuteWorkflow(ctx, opts, MyWorkflow)` and
    `workflow.ExecuteActivity(ctx, MyActivity, args)`. Dotted tail
    extraction: `pkg.MyWorkflow` → `MyWorkflow`.
  - **TypeScript/JavaScript**: `workflow.start(MyWorkflow, ...)` and
    `workflow.execute(MyWorkflow, ...)`.
  - **Python**: `start_workflow(MyWorkflow.run, args)` and
    `execute_workflow(MyWorkflow.run, args)` — method name explicit.
  - **Java (no Spring)**: `newWorkflowStub(X.class).method()` same as
    spring-temporal but only when generic detect fires.
- Dispatch resolution (`addEdgeFor`):
  - Workflow interface/class lookup by name; exactly-one-candidate
    discipline.
  - Implementor lookup via `implements` edges; if zero implements edges,
    the dispatch target IS the workflow class itself (Go/TS direct dispatch).
  - Method name: explicit (Python) or guessed (`Run` / `run` /
    `execute` / `Execute`) — first match in the implementor's file.
  - Enclosing function/method/constructor of the call site computed by
    line-range containment.
- Edge emission: `kind='calls'`, `subkind='temporal_dispatch'`, full
  line/col from the call site, `provenance='framework:temporal'`,
  confidence 0.85.
- `seen` set dedups (source, target, line, col) within a single Phase 3
  run.

## Notes

- The "workflow IS its own class" shortcut handles Go and TypeScript
  client patterns where there's no separate interface/impl split — the
  dispatch target is the type passed to `start`/`ExecuteWorkflow`.
- The method-name guesser uses convention: Go prefers exported `Run`,
  TS/Python lowercase `run`. First match wins. Real codebases that
  deviate (e.g. multiple workflow methods on one class) will produce
  no edge under the strict "exactly one method match" rule — same
  precision-over-recall trade as spring-temporal.
- Java-without-Spring path retained: a project that uses Temporal SDK
  in plain Java (no Spring) is detected by this generic resolver and
  the same `newWorkflowStub(X.class).method()` scanner fires. Spring
  projects exclusively use `spring-temporal`.
