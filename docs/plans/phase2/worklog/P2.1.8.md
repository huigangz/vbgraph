1. `every node read in src/db/queries.ts uses freshPredicate() or is allowlisted`
2. `every edge read in src/db/queries.ts uses freshPredicate() + visibleNodeIdPredicate() or is allowlisted`

## Test mechanism

String-based scan over `src/db/queries.ts`:

- **Read detection** — match lines containing `FROM nodes` / `FROM edges` (with optional alias) OR `JOIN nodes` / `JOIN edges`.
- **Write-statement skip** — line itself OR previous 5 lines contain `DELETE FROM <table>`, `INSERT INTO <table>`, or `UPDATE <table>`. Catches multi-line writes like:
  ```sql
  `DELETE FROM edges
   WHERE source IN (SELECT id FROM nodes …)`
  ```
  (Here the inner `SELECT id FROM nodes` is part of the DELETE's subquery, not a public read.)
- **Schema-statement skip** — `ALTER TABLE` / `CREATE INDEX`.
- **Comment skip** — lines starting with `*` (JSDoc) or `//`.
- **Helper-body skip** — the `NOT IN (SELECT id FROM nodes WHERE stale = 1 …)` body of `visibleNodeIdPredicate` is self-referential and is explicitly excluded.
- **Context window** — 25 lines on either side of the match line. Long enough to cover multi-line template strings where the predicate is appended several lines after the `FROM <table>` keyword.
- **Allowlist** — substring match against the surrounding context window for explicit allowlist entries. Each entry has a `reason` field documenting why this site is exempt.

## Why string-based not AST-based

- Surface area is one file (`queries.ts`). String matching is sufficient.
- AST parsing of TypeScript adds a dependency (or a heavyweight import) and would catch nothing string matching misses for the SQL-embedded-in-strings pattern.
- The guard runs in <100ms; any future contributor's iteration cost is negligible.

## Risk callouts

- **The guard's context window is fixed at 25 lines.** A future caller composing predicates 30+ lines away would silently pass. The pattern in `queries.ts` keeps predicates adjacent; if the convention ever changes, the window grows accordingly. Documented in the test file.
- **Allowlist drift**: if a method is renamed, its allowlist marker may no longer match. Each marker is a unique substring; rename + missed-update = guard re-flags the call site, forcing the contributor to update the allowlist explicitly. Self-correcting.
- **The third smoke test asserts the exact helper output strings** — `freshPredicate()` → `(stale = 0 OR staleness_visible = 1)`. If those strings ever change, the smoke test breaks first; downstream tests then break with clearer messages. Sentinel pattern.
