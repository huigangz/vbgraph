# P0.3 — SCIP symbol parser — Work Log

**Status:** Done.
**Date:** 2026-05-20

## Scope delivered

### New file — `src/extraction/scip/symbol-parser.ts`

- `parseScipSymbol(symbol) -> ParsedScipSymbol` — a recursive-descent parser for the full
  SCIP symbol grammar (transcribed from `scip.proto`):
  - `<scheme> ' ' <manager> ' ' <package-name> ' ' <version> ' ' (<descriptor>)+`, or
    the `local <local-id>` form.
  - Space escaping (`'  '` -> literal space) in the scheme/package fields; the `.`
    placeholder -> empty value for manager/package-name/version.
  - All eight descriptor productions: namespace `/`, type `#`, term `.`, meta `:`,
    macro `!`, method `<name>(<disambiguator>?).`, type-parameter `[name]`,
    parameter `(name)`.
  - Backtick-escaped identifiers, including `` `` `` -> literal backtick.
  - Emits `ParsedScipSymbol` with `scheme`, `package`, `descriptors[]`, `isLocal`, a
    dotted `qualifiedName`, and the original `raw` string. Structural errors throw
    `ScipSymbolParseError`.
- `hashScipSymbol(symbol) -> string` — stable node id, `scip:<32-hex>` (SHA-256 prefix).
  The hash is **symbol-only, never kind-salted**, so the same symbol resolves to the same
  `node.id` whether it is first seen as a definition or as a cross-file reference — which
  is what makes the P0.4 `scip_symbol_map` lookup correct. The `scip:` prefix cannot
  collide with tree-sitter ids (`<NodeKind>:<hash>`, and `scip` is not a `NodeKind`).
- `nodeKindForScipSymbol(parsed, scipKind?) -> NodeKind` — `SymbolInformation.kind`
  (SCIP 0.3+) wins when present and recognized; otherwise the trailing descriptor suffix
  decides. Includes the full numeric `SCIP Kind` enum -> `NodeKind` table; `Module (29)`
  -> `module` is called out as load-bearing for VB.NET.
- `descriptorSuffixToNodeKind(suffix)` — the suffix-only default mapping.

## Deviation / forward-pull from P0.8

`NODE_KINDS` (`src/types.ts`) gained `'constructor'` and `'event'` — needed so the SCIP
`Kind` map can emit them (`Constructor (9)` -> `constructor`, `Event (13)` /
`StaticEvent (78)` -> `event`). This is the P0.8 item "`NODE_KINDS` adds `'constructor'`
and `'event'`", pulled forward because P0.3's kind table produces them. Verified safe: no
exhaustive `switch`/`Record<NodeKind,_>` over node kinds exists (`kindBonus` is
`Record<string,_>`), so `tsc` stays clean. The rest of P0.8 is unaffected.

## Design notes

- `meta` (`:`) defaults to `NodeKind 'namespace'`, per the plan's P0.3 mapping. (The
  grammar itself calls `:` "meta — any purpose"; the concrete default is the plan's
  call and is overridden by `SymbolInformation.kind` whenever the indexer supplies one.)
- Empty descriptor names are tolerated (not all indexers are perfectly well-formed); a
  genuine parser desync is still caught because the following character then fails the
  suffix check.
