# P2.2.0 — Sync path audit (before write helpers)

**Status**: complete — feeds P2.2.1 through P2.2.5.
**Date**: 2026-05-24
**Decisions**: design doc Decisions 1, 2, 6, 7. P2.2 implements them on the write/sync side; P2.1 already implemented the read side.

## Existing sync flow

`ExtractionOrchestrator.sync()` at [src/extraction/index.ts:1158+](../../../src/extraction/index.ts#L1158):

1. **Detect changes** (git fast-path or full directory scan). Populates `filesToIndex[]` with new + modified files; calls `deleteFile()` for removed files.
2. **Load grammars** for the affected languages.
3. **For each file**: `await this.indexFile(filePath)` → `indexFileWithContent()` → `extractFromSource()` → `storeExtractionResult()`.
4. **`storeExtractionResult()`** at line 1083 calls `this.queries.deleteFile(filePath)` then inserts fresh tree-sitter rows.

**The problem (round 1 finding 1)**: `deleteFile()` ([queries.ts:1601](../../../src/db/queries.ts#L1601)) is provenance-blind. It nukes SCIP rows along with tree-sitter rows. So today's sync silently destroys any SCIP coverage when a file is edited.

## What P2.2 needs to add

### New module exports

```ts
// src/db/queries.ts
export const SCIP_FILE_PROVENANCES = ['scip', 'tree-sitter (scip-empty-fallback)'] as const;
```

Used by both per-file `markScipFileStale` and bulk `bulkMarkScipFilesStale` (and source-only edge predicate inside `markScipFileStale`'s SQL).

### New QueryBuilder methods

```ts
markScipFileStale(filePath: string, visible: 0 | 1): { nodesMarked: number; edgesMarked: number };
deleteFileTreeSitterRows(filePath: string): { nodesDeleted: number; edgesDeleted: number };
bulkMarkScipFilesStale(filePaths: readonly string[], visible: 0 | 1): { nodesMarked: number; edgesMarked: number; filesAffected: number };
isFileScipCovered(filePath: string): boolean;   // helper for sync's branching
```

Return-value reporting is for the regression tests; production callers ignore the counts.

### New sync-side helpers in `ExtractionOrchestrator`

```ts
// In src/extraction/index.ts
private isShadowCapable(lang: Language): boolean;   // thin wrapper around isLanguageSupported
private async indexFileShadow(filePath: string): Promise<ExtractionResult>;  // tree-sitter w/o deleteFile
```

`indexFileShadow` is `indexFile` minus the `deleteFile` call. The cleanest way: add a `mode: 'replace' | 'shadow'` parameter to `storeExtractionResult` so the shadow path skips the delete. (`'replace'` stays the default; existing call sites are unchanged.)

### Sync loop rewrite

The current per-file loop at [extraction/index.ts:1278-1290](../../../src/extraction/index.ts#L1278) becomes:

```
collect scipChanged[], nonScipChanged[]                    // partition once
if scipChanged.length > maxStaleFilesPerSync:              // Decision 6
  bulkMarkScipFilesStale(scipChanged, visible=1)
  warn user about scip-refresh
  // skip shadow extraction for the bulk batch
  for non-scip file: indexFile()  (unchanged)
else:
  for each scipChanged file F:
    lang = detectLanguage(F)
    if isShadowCapable(lang):
      markScipFileStale(F, visible=0)
      deleteFileTreeSitterRows(F)
      indexFileShadow(F)
    else:
      markScipFileStale(F, visible=1)                       // no grammar; visible-stale
      // no extraction
  for non-scip file: indexFile()  (unchanged)
```

### Config addition

```ts
// src/types.ts CodeGraphConfig
maxStaleFilesPerSync?: number;   // default 50; threshold for bulk-mark branch
```

## Open scoping questions (resolved here, not punted)

1. **Should `indexFile()` (the indexAll-callable path) gain shadow awareness?** No — `indexAll()` re-indexes from scratch; SCIP ingest happens before tree-sitter so deletion is fine. Only `sync()` needs the shadow branching.

2. **What about non-shadow-capable files NOT in `scip_documents`?** They were never SCIP-covered, so tree-sitter is the only valid path. Existing `indexFile()` (with its `deleteFile` call) is correct. No change.

3. **What about removed SCIP-covered files (git delete)?** Plan currently calls `deleteFile()` which removes everything. SCIP cleanup happens via STAGE B on next `scip-refresh`. **Decision**: this is acceptable for P2 — `deleteFile` on a removed file is correct (file is gone, no point keeping SCIP rows). Documented in worklog.

4. **What if the file's language detection changes (e.g. `.tsx` becomes `.jsx`)?** Edge case; existing behavior treats the new file as added. SCIP rows under the old path stay until next refresh. Acceptable.

5. **Cache invalidation ordering** (round 4 finding 1): each write helper invalidates cache BEFORE the SQL write. Required because the predicate-filtered `getNodeById` still serves cache hits without re-checking SQL freshness state. P2.1's design assumes the cache is invalidated before the row's stale-state is flipped.

## Risk callouts

- **`maxStaleFilesPerSync` threshold default of 50** is somewhat arbitrary. Plan keeps it configurable; P2 ships with 50 and tunes from user feedback. Lower values trigger bulk-mark on smaller branch switches; higher values let large refactors trigger N shadow extractions (slow but correct). Documented in the type.
- **`indexFileShadow` reuses `extractFromSource`** — same code path as `indexFile`. The only difference is the absence of `deleteFile`. Plus side: no parser duplication. Minus side: any future divergence (e.g. shadow-specific extraction tuning) needs a fork. Acceptable for now.
- **`storeExtractionResult` mode parameter** is a minor API expansion. The existing `'replace'` default keeps all internal callers (indexAll, indexFiles, the main batch loop) unchanged. New `'shadow'` mode is only used from `indexFileShadow`.
