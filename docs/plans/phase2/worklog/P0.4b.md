## Scope delivered

### `src/index.ts`

- New private `CodeGraph.cleanupIncompleteIngestions()`: queries
  `QueryBuilder.getIncompleteScipIngestions()` (rows with `completed_at IS NULL`), logs a
  one-line warning to **stderr** (safe for MCP stdio transports), and scoped-deletes each
  via `QueryBuilder.cleanupIncompleteScipIngestion()`.
- Wired into both `static async open()` and `static openSync()` — called right after the
  `CodeGraph` instance is constructed (migrations have already run inside
  `DatabaseConnection.open`), and before any `sync()`. `init()` / `initSync()` create a
  fresh DB, so they have nothing to recover and are deliberately left untouched.

The underlying `QueryBuilder.cleanupIncompleteScipIngestion()` /
`getIncompleteScipIngestions()` were delivered in P0.4. The cleanup is destructive, not
restorative — the warning tells the user to re-run the indexer.

### Test — `__tests__/p04b-crash-recovery.test.ts` (3 tests)

Ingests a synthetic `.scip` into a project DB, then forces `scip_ingestions.completed_at`
to NULL to simulate a crash before STAGE F:

- `openSync` garbage-collects the crashed ingestion — nodes/edges back to 0, and the
  `scip_ingestions` / `scip_documents` rows are gone.
- A *completed* ingestion survives `openSync` untouched.
- `async open` performs the same cleanup.
