## Behavior changes (CHANGELOG-worthy)

- **`getStats()` now excludes hidden-stale rows and dangling-endpoint edges** — matches the default query contract. Use `getStatsIncludingStale()` for raw totals or `getStaleSummary()` for the hidden/visible/fresh breakdown. To be called out explicitly in the `## [0.9.0]` CHANGELOG block (drafted in P2.6).
- All public node/edge queries filter hidden-stale nodes and edges with hidden-stale endpoints. Visible-stale rows pass through with `stale: true` on the returned objects. No public path returns hidden-stale data.

## What the guard test catches going forward

The CI bypass guard test (`__tests__/p21-no-bypass.test.ts`) ensures any future raw `SELECT … FROM nodes` or `SELECT … FROM edges` in `src/db/queries.ts` is either:
1. Composed with `freshPredicate(` (and `visibleNodeIdPredicate(` for edges), OR
2. Explicitly added to the `NODE_ALLOWLIST` / `EDGE_ALLOWLIST` with a rationale.

The guard surfaced 4 PUBLIC sites that my initial single-line grep missed (multi-line template strings, joined-table selects, comma-separated FROM). Final count: **18 PUBLIC node sites + 7 PUBLIC edge sites** all properly wired.

## Lessons captured for P2.2/P2.3

- **Run the CI guard early** when writing new prepared statements — it caught 4 misses in <1s each iteration vs running the full suite.
- **Multi-line templates and JOIN targets are easy to overlook** with line-based grep. Use the 25-line context window guard from day one.
- **Test fixtures that pre-date a schema column** need updating when migrations reference that column — the v5→current test fixture needed `nodes`/`edges` tables added because v7's partial-index DDL needs them.
