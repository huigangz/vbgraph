### Module-level constant

```ts
export const SCIP_FILE_PROVENANCES = [
  'scip',
  'tree-sitter (scip-empty-fallback)',
] as const;

const SCIP_FILE_PROVENANCES_SQL =
  "('scip', 'tree-sitter (scip-empty-fallback)')";
```

Exported because P2.6 tests and (potentially) external diagnostic tools want to assert against the canonical list. The SQL variant is module-private — only the helpers below need it inline.

### QueryBuilder.`isFileScipCovered(filePath)`

`SELECT 1 ... FROM scip_documents WHERE source_file_path = ? LIMIT 1`. Returns true if any `.scip` index covers this file. Used by sync's branching: SCIP-covered files take the shadow path, others take the existing replace path.

Returns `boolean` to keep callers terse. The defensive `row !== undefined && row !== null` check matches the existing pattern in `getFileByPath` (the WASM adapter returns `null` for misses while better-sqlite3 returns `undefined`).

### QueryBuilder.`markScipFileStale(filePath, visible)`

Two SQL writes inside one method, both targeting `SCIP_FILE_PROVENANCES`:

1. **Nodes**: `UPDATE nodes SET stale=1, staleness_visible=? WHERE file_path = ? AND provenance IN (...)`
2. **Edges (source-only per Decision 2)**: `UPDATE edges SET stale=1, staleness_visible=? WHERE source IN (SELECT id FROM nodes WHERE file_path = ? AND provenance IN (...))`

Returns `{ nodesMarked, edgesMarked }` counts for regression-test assertions. Production callers can ignore.

### Cache invalidation pattern

**Inline before SQL writes**, file-scoped:

```ts
for (const [id, node] of this.nodeCache) {
  if (node.filePath === filePath) {
    this.nodeCache.delete(id);
  }
}
```

Same pattern as existing `deleteNodesByFile` ([queries.ts:381](../../../src/db/queries.ts#L381)). Why before, not after: `getNodeById`'s cache check at queries.ts:469 runs BEFORE the SQL — if we invalidated after marking, a concurrent `getNodeById` between the SQL update and the cache invalidation would return a cached fresh row that's actually stale-and-hidden. Better-sqlite3 is sync-only so true concurrency is impossible, but the invariant "cache invalidate FIRST" generalizes correctly to any future async adapter.

## Risk callouts

- **Edge marking uses `provenance LIKE 'scip%'`-style inner SELECT** — actually no, uses `provenance IN (...)` against `SCIP_FILE_PROVENANCES`. Subtle: this catches edges sourced from `scip-empty-fallback` rows AND from `'scip'` rows. The reverse — an edge whose source is a fallback row targeting a SCIP row — gets marked stale only via the source side, which is the source-only invariant.
- **The edge `UPDATE` does not also check `edges.provenance LIKE 'scip%'`** — it relies entirely on the source-node predicate. Decision: this is correct. An edge sourced from a SCIP node is by construction SCIP-emitted (or scope-resolved against SCIP nodes). Both should be marked stale when the source file drifts. The freshness invariant in `upsertGraphEdge` clears the flag on next re-emission.
- **`isFileScipCovered` query returns `1` as integer column** — defensive cast `row !== undefined && row !== null` works on both backends. Verified against the existing pattern.
