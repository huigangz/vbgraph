# P1.5 PR-4 — express migration

**Status**: complete
**Date**: 2026-05-23

## What landed

`src/resolution/frameworks/express.ts` rewritten as a Phase 3 resolver.

- `detect` — unchanged.
- `synthesize` — same route regex as the legacy `extract`. Iterates
  `graph.getAllFiles()`, filters to `.js`/`.mjs`/`.cjs`/`.ts`/`.tsx`, reads
  stripped content per file's language. Emits one `route` node per
  matched `(app|router).METHOD('/x', …)` site, IDs namespaced
  `framework:express:route:…`, all with `provenance='framework:express'`.
- `augment` — for each `framework:express` route, parses the route's
  source line to recover `(middleware, …, handler)` ident chain.
  Resolves each ident via `getNodesByName` (kind ∈ {method, function}),
  with strict precision: single global match OR unique same-file match;
  ambiguity → no edge. Emits `references/convention` edges (NULL line/col,
  per allowlist). Tags: `route-handler` on the handler, `express:middleware`
  on each middleware.
- `resolve` field removed (subsumed by P0.5b scope resolver for ts/js).
- `extract` field removed.

## Tests

- Three `expressResolver.extract` tests in `frameworks.test.ts` rewritten
  to drive `synthesize` via `makeStubGraphView` (added in the aspnet PR).
  The middleware-chain test still asserts the route node shape; the
  middleware→handler edge construction is exercised by Phase 3 orchestrator
  tests already.
- The strip-comments regression case for express was also rewired to
  `synthesize`.

All 60 tests across `frameworks.test.ts` + `p1-phase3-orchestrator.test.ts` pass.

## Notes

- Augment's handler resolution is conservative — multiple global
  candidates without a same-file disambiguation → no edge. This trades
  recall for precision: a wrong route→handler edge would mislead
  callers tracing the request graph, so we'd rather skip an unresolved
  case than emit a guess.
- The middleware-tagging path is straightforward but currently only
  exercised by integration testing (not unit-test fixtures). A
  per-resolver augment test that pre-seeds method/function nodes and
  verifies edge + tag emission would land naturally alongside this
  resolver's first user report — kept out of this PR to avoid
  fixture-creep when the orchestrator-level tests already cover the
  contract.
