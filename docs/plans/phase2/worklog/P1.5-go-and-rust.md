# P1.5 PR-11 + PR-12 — go + rust migrations

**Status**: complete
**Date**: 2026-05-23

## go (`src/resolution/frameworks/go.ts`)

- `detect` — unchanged.
- `extract` → `synthesize`: same gin/echo/chi/net-http regex
  (`router|r|mux|app|e.METHOD("/x", handler)`). `HandleFunc` / `Handle`
  map to `ANY`. IDs namespaced `framework:go:route:…`, provenance
  `framework:go`.
- `resolve` → `augment`: per-route source-line re-parse to recover the
  handler ident, single-candidate resolution (function/method kind),
  same-file preference, emits `references/convention` + `route-handler`
  tag.
- Legacy suffix lookups (`*Handler`, `*Service`, `*Store`, PascalCase
  struct, middleware) all dropped — heuristic best-effort against
  directory conventions.
- 2 `goResolver.extract` tests + 1 strip-comments regression rewired to
  `synthesize`.

## rust (`src/resolution/frameworks/rust.ts`)

- `detect` — unchanged.
- `extract` → `synthesize`: Actix/Rocket `#[get("/x")]` attribute routes
  AND axum `.route("/x", get(handler))` DSL. IDs namespaced with
  `route-attr` vs `route-axum` prefixes so the same route file at the
  same line can carry both shapes without collision.
- `augment`: per-route source-line re-parse via `findRustHandlerName`
  (axum same-line, attribute next-5-lines). Single-candidate resolution
  + same-file preference + `route-handler` tag.
- **`resolve` PARTIALLY RETAINED**: the cargo-workspace crate-name →
  crate-root module resolution stays — it's load-bearing for cross-crate
  `imports` edges and tested by three rustResolver.resolve tests in
  `frameworks.test.ts`. The PR strips the suffix-based by-name patterns
  (`*_handler`, `*Service`, PascalCase struct) but keeps the module
  pattern (Pattern 4 from the legacy code).
- 1 `rustResolver.extract` test + 1 strip-comments regression rewired
  to `synthesize`. The three cargo-workspace tests continue to call
  `rustResolver.resolve(...)` and pass unchanged.

## Tests

All 64 across `frameworks.test.ts` + `frameworks-integration.test.ts` +
`p1-phase3-orchestrator.test.ts` pass.

## Notes

- Rust joins vue + svelte as a resolver that intentionally retains
  `resolve`. The pattern is consistent: when a resolver's per-ref logic
  provides something that scope/import resolution cannot (framework
  symbols, build-system module mapping), `resolve` stays. The plan's P3
  cleanup is the right place to redesign these patterns globally.
- Both go and rust now emit conventional route→handler edges where the
  handler exists in the indexed graph. Conservative single-match-only
  precision matches aspnet/express.
