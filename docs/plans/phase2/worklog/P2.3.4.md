# P2.3.4 — Config fields: `scipRefreshCommand` + `scipRefreshOutputPath`

**Status**: complete
**Date**: 2026-05-24
**Decisions**: design doc § P2.3 (plan line 1478 — default `'scip-dotnet index ./'`).

## Changes (`src/types.ts`)

### `CodeGraphConfig.scipRefreshCommand?: string | string[]`

- Default: `'scip-dotnet index ./'` (matches plan).
- Union type — accepts a single string (whitespace-tokenized) OR a pre-tokenized array (for paths with spaces).
- Documented in JSDoc with both forms.

### `CodeGraphConfig.scipRefreshOutputPath?: string`

- Default: `'./index.scip'` (the scip-dotnet convention).
- Resolved relative to the project root by the CLI.
- Separate from the command so the user can override one without the other.

### `DEFAULT_CONFIG`

```diff
  maxStaleFilesPerSync: 50,
+ scipRefreshCommand: 'scip-dotnet index ./',
+ scipRefreshOutputPath: './index.scip',
};
```

## Why two fields (command + output path)

If `scipRefreshCommand` already embeds the output (e.g. `'scip-dotnet index ./ --output foo.scip'`), the ingest step needs to know where to look. Splitting the output path into its own field is the simplest decoupling — the user setting a custom command just sets both fields.

Alternative considered: parse `--output` out of the command. Rejected — too brittle (different indexers use different flag names: `--output`, `-o`, `--out`, positional).

## Validation

- `npx tsc --noEmit` clean.
- No new behavioral surface yet — P2.3.3 wires the config into the CLI.

## Risk callouts

- **String vs array**: parser in P2.3.3 needs to handle both. Single-string form uses naive whitespace split — paths with spaces will mis-tokenize. JSDoc points to the array form for that case.
- **Default assumes scip-dotnet** — appropriate because Phase 2's primary user is the .NET/VB.NET cohort. Users with other indexers must override. CHANGELOG (P2.6) calls this out.
