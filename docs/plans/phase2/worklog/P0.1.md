## Scope delivered

### New file — `src/extraction/scip/streaming-decoder.ts`

The three streaming entry points from the spec, plus the typed shapes they emit:

- `readScipMetadata(scipPath) -> Promise<ScipMetadata>` — scans for `Index.metadata`
  (field 1) and returns on first sight (SCIP writes metadata first, so the common case
  does not read the whole file), but tolerates any field ordering.
- `iterateScipDocuments(scipPath) -> AsyncGenerator<ScipDocument>` — streams field 2.
- `iterateScipExternalSymbols(scipPath) -> AsyncGenerator<ScipSymbolInformation>` —
  streams field 3.
- `ScipDecodeError` — the single corruption/truncation signal P0.4c's STAGE A pre-scan
  will catch.
- Typed `Scip*` interfaces (`ScipDocument`, `ScipMetadata`, `ScipOccurrence`,
  `ScipSymbolInformation`, `ScipRelationship`, `ScipToolInfo`) — camelCase, matching
  protobufjs's decoded field names (verified empirically before writing the decoder).

**Implementation honoring the plan's "mandatory constraints":**

- No `protobufjs.Type.decode(fs.readFileSync(...))` — the file is never read whole.
- A hand-rolled wire-level reader (`StreamByteReader`) over `fs.createReadStream`
  (~64 KB chunks). It parses the top-level `Index` tag stream itself and decodes only
  one length-delimited submessage at a time via `Document.decode` / `SymbolInformation.decode`
  / `Metadata.decode`.
- `scanIndexFields` dispatches per protobuf tag: requested fields are read and yielded;
  every other field (including the other repeated field, non-`LEN` wire types, and
  **unknown field numbers** from a future SCIP schema) is skipped without allocation.
  Field ordering is therefore irrelevant and the parser is forward-compatible.
- Each public entry point opens its **own** independent read stream; nothing is buffered
  globally. The stream is `destroy()`-ed in a `finally`, so early `break` / early-return
  (`readScipMetadata`) releases the file handle.
- Submessages are decoded to plain detached objects via `Type.toObject` (`defaults:true`,
  `arrays:true`, `enums:Number`, `longs:Number`) — no protobufjs prototypes retained,
  easier on GC.

### New file — `__tests__/helpers/scip-fixtures.ts`

Shared test helper (P0.4 / P0.10 will reuse it). Builds valid `.scip` files by
**streaming** each encoded submessage (`writeSyntheticScip` for small explicit fixtures,
`writeLargeSyntheticScip` for stream-generated large ones) so the generator never buffers
the whole `Index`. Supports out-of-order fields (`externalSymbolsFirst`, `metadataLast`)
and `truncateScipFile` for corruption tests.

### New file — `__tests__/p01-streaming-decoder.test.ts` (8 tests)

- Round-trips documents, occurrences, nested symbols; reads metadata/tool info.
- External-symbol stream is independent of the document stream over the same file.
- Empty file -> zero documents, `readScipMetadata` throws.
- Field-order independence: `external_symbols` before `documents`, `metadata` last —
  all three readers still work.
- Truncation mid-document and truncation inside the leading varint header both reject
  with `ScipDecodeError`.
- **Memory:** an >80 MB fixture (60 000 documents, 1.8 M occurrences, 8 000 external
  symbols) iterates with peak RSS delta asserted `< 64 MB`. A `--expose-gc`-gated branch
  additionally asserts no net leak (`< 32 MB` post-GC).

## Verification

- `npx tsc --noEmit` — clean.
- `npx vitest run __tests__/p01-streaming-decoder.test.ts` — **8/8 pass**, full file 2.8 s
  (the large-file memory test alone 2.4 s — comfortably streaming).

## Notes / deviations

- The plan's P0.1 verification says "500 MB fixture". The P0.1 test uses an >80 MB fixture
  (large enough that buffering-the-whole-file would blow the 64 MB bound, while keeping the
  unit test fast). The literal 500 MB / 1 M-definition / 100 k-external-symbol benchmark
  remains assigned to P0.10's `scip-ingester.test.ts`, which `writeLargeSyntheticScip`
  already supports by raising its parameters.
- The strict "RSS returns to baseline after GC" assertion needs `--expose-gc`, which the
  vitest harness does not pass by default; that branch is therefore conditional. The
  unconditional peak-RSS-delta bound on an >80 MB file is itself a robust streaming proof
  (V8 GCs under allocation pressure during the 60 k-document loop).
