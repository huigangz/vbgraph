## Sync path: before vs after

**Before P2.2** (every file = `await this.indexFile(filePath)`):

```
for filePath in changed:
  indexFile(filePath)
    → storeExtractionResult(...)
        → queries.deleteFile(filePath)  // provenance-blind, nukes SCIP rows
        → insert fresh tree-sitter rows
```

**After P2.2** (partition + threshold + shadow):

```
partition changed:
  scipChanged[]    ← isFileScipCovered === true
  nonScipChanged[] ← isFileScipCovered === false

if scipChanged.length > maxStaleFilesPerSync:
  bulkMarkScipFilesStale(scipChanged, visible=1)   // visible-stale
  logWarn("Branch switch detected; run scip-refresh")
  // skip per-file shadow for the bulk batch

for filePath in changed:
  if SCIP-covered AND bulk-branch-switch: continue
  if SCIP-covered:
    if isLanguageSupported(lang):
      markScipFileStale(F, 0)                       // hide SCIP rows
      deleteFileTreeSitterRows(F)                   // clear prior shadow
      indexFileShadow(F)                            // re-extract (mode='shadow')
    else:
      markScipFileStale(F, 1)                       // visible-stale; no extraction
    continue
  indexFile(filePath)                               // unchanged path
```

## Observable behavior changes

1. **`sync` no longer wipes SCIP rows** when editing a SCIP-covered file. The pre-P2 behavior silently destroyed SCIP coverage on every edit; P2.2 preserves it.

2. **Editing a SCIP-covered file in a shadow-capable language** (most languages): SCIP rows go hidden-stale, tree-sitter shadow runs. Queries return shadow data. Status (P2.4) will report hidden-stale counts.

3. **Editing a SCIP-covered file in a non-shadow-capable language** (rare — `unknown` is the only "unsupported" today, and even those don't reach sync because `isLanguageSupported` filters them out earlier in `indexFile`): SCIP rows go visible-stale; queries return SCIP data with `Node.stale = true`. This path is the safety net for future languages where SCIP coverage exists but no tree-sitter grammar does.

4. **Branch switch with > 50 changed SCIP-covered files**: bulk-mark + CLI warning. User sees:
   ```
   [codegraph] Branch switch detected (123 SCIP-covered files changed;
     threshold = 50). Skipping per-file shadow extraction; SCIP data is
     now marked stale-but-visible. Run 'codegraph scip-refresh' to
     restore precision.
   ```

5. **Non-SCIP-covered files**: behavior identical to pre-P2.2. The new code path is purely additive.

## Risk callouts (consolidated)

- **Shadow path adds ~10ms per SCIP-covered file** (3 SQL operations + tree-sitter extraction). For batches up to 50, total overhead ≤ 500ms — acceptable. Above 50, bulk-mark kicks in.
- **`indexFileShadow` duplicates `indexFile`'s read/stat path** ~50 lines. Refactoring deferred — acceptable maintenance cost vs. risk of breaking either path.
- **`storeExtractionResult` `mode` parameter** is a private-method signature change. All in-tree callers default to `'replace'`; external embedders extending the class (rare) would need to opt in. Documented.
- **`maxStaleFilesPerSync = 50`** is an opinionated default. Tunable. Users running on monorepos with frequent large branch switches can raise it; users prioritizing per-file precision can lower it.
- **`bulkMarkScipFilesStale` runs full JSON-each scans** — for batches up to ~1000 files, performance is bounded by `idx_nodes_file_path`. Above that, consider chunking. Documented as a P3 optimization.
- **Cache invalidation always runs BEFORE SQL mutation** — verified in all 4 write helpers. Round 4 finding 1 closed.
