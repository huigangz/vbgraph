# P1.5 PR-7 — svelte migration

**Status**: complete
**Date**: 2026-05-23

## What landed

`src/resolution/frameworks/svelte.ts` rewritten:

- `detect` — unchanged.
- `extract` → `synthesize`:
  - Iterates `graph.getAllFiles()`, filters to SvelteKit route files
    (the closed set `+page.svelte` / `+page.ts` / `+layout.*` /
    `+server.*` / `+error.svelte`).
  - For each match, computes the SvelteKit route path from the
    directory under `routes/` (parameter syntax preserved:
    `[slug]` → `:slug`, `[...rest]` → `*rest`, `[[opt]]` → `:opt?`).
  - Emits one `route` node per file, namespaced ID
    `framework:svelte:route:…`, `provenance='framework:svelte'`.
- `resolve` RETAINED for:
  - Svelte 5 runes (`$state`, `$derived`, `$effect`, etc.) — compiler-provided.
  - `$store` auto-subscribe — needs context.getNodesByName lookup against
    a stripped name.
  - `$app/*` and `$env/*` virtual modules.
  - `$lib/*` alias dropped — covered by import resolver.
  - PascalCase component lookup dropped — covered by import resolver.
- `extract` field removed.

## Tests

`svelteResolver.extract` smoke test replaced with two
`svelteResolver.synthesize` tests:

1. Shape smoke.
2. Route extraction from `src/routes/blog/[slug]/+page.svelte` —
   asserts route path `/blog/:slug`, kind, provenance.

All 63 tests across `frameworks.test.ts` + `p1-phase3-orchestrator.test.ts` pass.

## Notes

- Svelte mirrors the Vue migration shape: synthesize covers routes,
  resolve retained for framework-built-in symbols. Same P3 deferred work
  (a global "framework-provided names" registry would let us drop the
  retained `resolve` field).
- The legacy resolver synthesized only routes (no middleware, no
  components — component nodes are extracted by `svelte-extractor.ts`).
  The migration preserves that scope exactly.
