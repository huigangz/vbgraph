## Changes (`src/bin/codegraph.ts`)

### New helper: `formatRelativeTime(iso)`

Maps an ISO 8601 timestamp to `"2h ago"` / `"3d ago"` / `"5mo ago"`. Returns the original string on parse failure. Used by the "Last refresh" line.

### Text output additions

Two new sections inserted between `Backend:` and `Nodes by Kind:`:

**Staleness** (rendered only when `stale.hiddenStale.files + stale.visibleStale.files > 0`):
```
Staleness:
  Shadow active:  3 file(s) — 47 nodes hidden behind tree-sitter shadow
  Needs refresh:  1 file(s) — 12 nodes shown stale (no tree-sitter grammar)
  Raw totals:     12,580 nodes / 28,123 edges (filtered: 12,521/28,049)
```

When fresh, the section is omitted entirely — no noise on a clean DB.

**SCIP** (always rendered when initialized):
```
SCIP:
  Last refresh:  2h ago — 1,234 file(s) in 5.6s
  csharp       Tier 1 SCIP (scip-dotnet)
  vbnet        Tier 0 tree-sitter — upgrade: dotnet tool install -g scip-dotnet
  typescript   Tier 0 tree-sitter
  ...
ℹ Run "codegraph scip-refresh" to restore SCIP precision
```

The refresh hint at the bottom fires only when `needsRefresh = true`.

## Why two sections (Staleness vs SCIP)

- **Staleness** answers "what's drifted since last refresh" — purely a sync-side concern. Skippable when clean.
- **SCIP** answers "how is each language indexed today" — independent of drift. Always shown so users discover Tier-0/Tier-1 distinctions even on a clean DB.

Keeping them separate also lets a future user grep `codegraph status | grep -A 2 Staleness` for clean monitoring.

## What's NOT in this PR

- **Manual refresh time prediction** ("based on last refresh, ~5s expected") — out of scope.
- **Per-file stale list** — too noisy for status. Users wanting it can `cat .codegraph/scip-last-refresh.json` plus query DB directly. P3 if requested.
- **MCP exposure** — `codegraph_status` MCP tool already returns `getStats()`; expanding it to include staleness is P3.

## Validation

- `npx tsc --noEmit` clean.
- `npm run build` succeeds.
- `node dist/bin/codegraph.js status --json` on an uninitialized project returns the existing `{ initialized: false, projectPath }` shape — backward compatible.
- Initialized-project paths covered by P2.4.6 tests.

## Risk callouts

- **`getLanguageTiers()` is async** — added an `await` in the status handler. The handler was already an `async` arrow; no signature change.
- **`languageTiers` ordering by file count descending** — most-relevant language first. Could be alphabetical instead; user feedback in P3 if needed.
- **Color uses `chalk`** — already imported; no new dependency. Tier label is green for Tier 1, gray for Tier 0, yellow for the upgrade hint.
- **`Raw totals` line only renders on a delta** — avoids noise on a clean DB. When non-zero stale exists AND the filtered counts equal raw (impossible by design), the line is also skipped — defensive.
- **JSON shape change adds 5 fields**: `stale`, `rawTotals`, `lastScipRefresh`, `languageTiers`, `needsRefresh`. Existing consumers continue to work (they ignore unknown fields). P2.6 CHANGELOG calls this out as additive.
