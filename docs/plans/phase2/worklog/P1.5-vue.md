# P1.5 PR-6 — vue migration

**Status**: complete
**Date**: 2026-05-23

## What landed

`src/resolution/frameworks/vue.ts` rewritten:

- `detect` — unchanged.
- `extract` → `synthesize`:
  - Nuxt page routes from `pages/**/*.vue` retained, `route` kind,
    namespaced ID `framework:vue:route:…`.
  - Nuxt API routes from `server/api/**` retained, `route` kind,
    namespaced ID `framework:vue:apiroute:…`.
  - **Removed**: the legacy synthesis of middleware files as `kind='function'`
    nodes. That violated Node-kind discipline (the middleware file's
    function is already extracted by tree-sitter; a fictitious additional
    `function` node duplicates identity). If future caller analysis needs
    a discoverable "middleware" facet, the right shape is a tag on the
    existing function node — not a synthesized node.
- **`resolve` field RETAINED** (intentionally not removed):
  - Vue 3 compiler macros (`defineProps` / `defineEmits` / `defineExpose` /
    `defineOptions` / `defineSlots` / `defineModel` / `withDefaults`) —
    these are compiler-provided, not declared in user code; scope resolver
    cannot find them. Resolve-to-self at confidence 1.0 keeps them out of
    `unresolved_refs`.
  - Nuxt auto-imported composables (`useFetch`, `useRouter`, etc.). Same
    rationale.
  - Nuxt virtual modules (`#imports`, `#components`, etc.). Same.
  - **DROPPED**: `@/` and `~/` alias resolution — covered by
    `loadProjectAliases` in the import resolver.
  - **DROPPED**: PascalCase component lookup — covered by the import
    resolver's `.vue` file resolution and P0.5b scope index.
- `augment` — omitted. Per the plan, vue augment would emit template→methods
  `calls` edges; `vue-extractor.ts` already does SFC decomposition and
  produces those edges. Adding a Phase 3 augment that duplicates that
  work would create dedup load; deferred.

## Tests

No vue-specific tests in `frameworks.test.ts` (only the smoke test
inventory targets aspnet/express/react/svelte/laravel/django/flask/fastapi/rails/go/rust).
All 62 tests across `frameworks.test.ts` + `p1-phase3-orchestrator.test.ts`
still pass after the vue rewrite.

## Notes

- Vue is the first migrated resolver that DOES NOT remove `resolve`. The
  pattern is documented inline: framework-built-in symbols (compiler
  macros, auto-imports, virtual modules) need framework-specific
  resolution that the scope / import resolvers cannot provide. The P3
  cleanup that retires strategy-1 entirely will need a parallel mechanism
  — e.g., a global "framework-provided names" set that the orchestrator
  uses to short-circuit unresolved refs.
- The legacy `extract` block in `tree-sitter.ts:2557` short-circuits via
  `if (!fw.extract) continue` for vue now, since the field is removed.
