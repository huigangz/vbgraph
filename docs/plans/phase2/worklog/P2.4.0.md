## Tier detection algorithm

For each language `L` present in `stats.filesByLanguage`:

1. `scipNodeCount` = `COUNT(*) FROM nodes WHERE language = L AND provenance = 'scip'` — quick lookup.
2. `treeSitterNodeCount` = `COUNT(*) FROM nodes WHERE language = L AND provenance LIKE 'tree-sitter%'`.
3. `scipIndexerAvailable` = the installed-indexer coverage map contains `L`.
4. `tier`:
   - `'tier-1'` if `scipNodeCount > 0` (SCIP nodes exist in DB for this language).
   - `'tier-0'` otherwise.
5. `installHint` = if `scipNodeCount === 0` AND no installed indexer covers `L`, look up `SCIP_INDEXERS` for an indexer that does and surface its `installHint`. Otherwise null.

Note: a language can be `tier-1` (SCIP nodes exist) WITHOUT the indexer being installed currently (someone ingested SCIP earlier; uninstalled the tool). That's fine — the tier reflects what's IN THE DB, not what's REINSTALL-ABLE.

## Risk callouts

- **`getStaleSummary` on every status call** runs a full-table SUM(CASE). On a 200k-node DB, ~50ms (well under the 200ms threshold P2.6 covers). Acceptable.
- **`getLanguageTiers` calls `detectInstalledScipIndexers`** which spawns probe processes (~5 indexers × 50ms = ~250ms first call). Cached in-process per the existing implementation — second call is free. CLI is one process, one status call: ~250ms total overhead. Acceptable for a status command.
- **Sidecar JSON parse** could throw on malformed file. Wrap in try/catch; null means "never refreshed" or "corrupt sidecar". Status doesn't distinguish — both render as "Never refreshed".
- **Per-language tier display** could get noisy on polyglot repos (15+ languages). Strategy: only show languages with `filesInRepo > 0` (which is already the filter for "Files by Language"); within those, only show the tier line if tier=tier-0 AND an indexer is installable. Otherwise the line is "C#: Tier 1 SCIP (scip-dotnet)" — terse. Tunable in P2.4.4.
