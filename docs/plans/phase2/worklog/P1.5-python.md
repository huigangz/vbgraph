# P1.5 PR-8 — django + flask + fastapi migration

**Status**: complete
**Date**: 2026-05-23

## What landed

`src/resolution/frameworks/python.ts` rewritten end-to-end. Three resolvers
in one file, one PR (per plan PR-8: "they share Python machinery").

For each of `djangoResolver`, `flaskResolver`, `fastapiResolver`:

- `detect` — unchanged.
- `extract` → `synthesize`:
  - django: route nodes from `path(...)`, `re_path(...)`, `url(...)` —
    same regex, kept as-is. ID prefix `framework:django:route:…`.
  - flask: route nodes from `@app.route('/x', methods=[...])` decorators
    with the next-line `def handler`. ID prefix `framework:flask:route:…`.
  - fastapi: route nodes from `@app.METHOD('/x')` decorators. ID prefix
    `framework:fastapi:route:…`.
- `resolve` removed for all three:
  - django: `*Model` / `*View` / `*Form` suffix lookups dropped — P0.5b
    scope resolver covers Python file-local refs.
  - flask: `_bp`/`_blueprint` variable lookup dropped — same reason.
  - fastapi: `_router` / `Depends(...)` lookups dropped — same reason.

The shared helper `resolveByNameAndKind` / directory-pattern constants
are deleted along with the resolve paths.

## Tests

Updated `__tests__/frameworks.test.ts`:

- 6 `djangoResolver.extract` tests → `djangoResolver.synthesize` tests.
  Dropped `references` assertions (which only made sense for the legacy
  pipeline-emitting-unresolved-refs flow); the route node shape
  assertions stay. The include() variant test now just asserts the
  route node — the include's `'imports'` ref kind was the legacy hint
  that included urls form a sub-graph; reconstructing that in the new
  shape requires augment work, deferred.
- 2 `flaskResolver.extract` tests → `synthesize` tests.
- 2 `fastapiResolver.extract` tests → `synthesize` tests.
- 3 strip-comments regression tests (django/flask/fastapi) rewired to
  `synthesize`. Comment / docstring suppression behavior identical to
  legacy because both paths route through `stripCommentsForRegex`.

All 63 tests across `frameworks.test.ts` + `p1-phase3-orchestrator.test.ts` pass.

## Notes

- `augment` is omitted for all three Python resolvers. The legacy flow
  emitted `UnresolvedRef`s that flowed through Strategy 2+ resolution;
  with synthesize emitting only nodes, the route→handler `calls` edges
  are reconstructed by tree-sitter's normal call-extraction pass on the
  `urls.py`/decorator-target functions. A future augment can emit
  explicit route→handler `references/convention` edges (mirroring aspnet
  / express patterns) when there's a measured recall gap.
- The legacy `references` array for include() was the only meaningful
  signal lost. If a future user needs a discoverable "this urls module
  includes that one" edge, the right shape is a `references/convention`
  edge from the route to the included module-level file/module node in
  augment.
