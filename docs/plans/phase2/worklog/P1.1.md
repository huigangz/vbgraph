  - New migration entry version 6: creates `node_tags` table + two indexes

- `src/db/schema.sql`:

### QueryBuilder methods

Added a new `Phase 3 — node_tags + framework purge + transaction wrapper`
section to `src/db/queries.ts` (between the existing graph-edge helpers and
the SCIP block), holding:

- `insertNodeTag(nodeId, tag, addedBy)` — single-row `INSERT OR IGNORE`,
  no inner transaction. First-writer-wins on `added_by`. Callers do tag
  validation and node-existence checks; FK violation throws.
- `getNodesByTag(tag)` — `INNER JOIN node_tags` on `nodes`, mapped through
  `rowToNode`. Uses `idx_node_tags_tag`.
- `transaction<T>(fn)` — thin delegate to the underlying adapter's
  `transaction(fn)()`. Phase 3's sole transaction boundary; nesting is the
  caller's responsibility to avoid.
- STAGE 0 purge helpers (used in P1.4, declared here to keep all framework /
  Phase-3 surface in one section):
  - `stripFrameworkContributionsFromMergedEdges()` — inline CASE ladder
    mirroring `defaultConfidence` in `src/types.ts:300`. Strips framework
    entries from `provenances[]` AND recomputes `confidence` from survivors,
    only on rows whose primary is non-framework AND which have a framework
    contributor. Comment cross-references the metadata-ownership rule and
    the test that guards against CASE/`defaultConfidence` drift.
  - `deleteAllFrameworkTags()` — `WHERE added_by LIKE 'framework:%'`.
  - `deleteFrameworkPrimaryEdges()` — `WHERE provenance LIKE 'framework:%'`.
  - `deleteFrameworkNodes()` — `WHERE provenance LIKE 'framework:%'`. The
    cascade on `node_tags` is redundant given the prior tag delete, but
    cheap.
- `invalidatePhase3Caches()` — clears `QueryBuilder.nodeCache`. Documented as
  the explicit flush after raw-SQL DELETEs that bypass `insertNode` /
  `deleteNode` cache invalidation.
