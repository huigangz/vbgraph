## Scope delivered

### The parity methodology

> Originally built at `__tests__/parity/parity-harness.ts`; relocated to
> `src/parity.ts` when the `codegraph parity` CLI was added (see below).

The hinge decision in the planning log was that the valuable thing to borrow is the
*methodology* — "the same edge from either backend must come out the same way" — not a
specific scope algorithm. That methodology is delivered in full:

- `EdgeFingerprint` = `(sourceQualifiedName, targetQualifiedName, kind)` — line/col-free.
- `buildParityReport(scipEdges, treeSitterEdges, qualifiedNameOf)` — classifies every
  fingerprint as `shared` / `scipOnly` / `treeSitterOnly`, and emits a `ParityRow` per
  fingerprint carrying `scipCallSites` / `treeSitterCallSites` / `missedSites` (distinct
  `line:col` counts) so a missed call site is not hidden by fingerprint collapsing.
- `assertEdgesEquivalent(...)` — fails on a missed call site of a **shared** fingerprint,
  on an unexpected `scipOnly` edge, or on **any** `treeSitterOnly` edge; accepts
  compiler-magic divergences via `AllowedDivergence`.
- `VBNET_ALLOWED_DIVERGENCE` — the `My.*` / project-level `Imports` / `WithEvents`+`Handles`
  / late-binding categories SCIP legitimately resolves alone.
- `qualifiedNameResolver(nodes)` — node-id -> qualified-name helper.

### `src/resolution/scope-index.ts` — minimal scope index

- `ScopeIndex` (`fileScope` / `classScope` / `resolve`), `SymbolRef`, `ScopeUseSite`.
- `buildScopeIndex(qb)` — **graph-backed**: file scope = a file's declaration nodes;
  class scope = a class's `contains` members; `resolve` walks class scope (which shadows)
  then file scope. Memoized for the index's lifetime.

  **Design choice:** the plan described per-language tree-sitter scope walkers. The
  implementation instead resolves against the *already-extracted* `nodes` + `contains`
  graph, which makes it language-agnostic — it covers C#, VB.NET, Java, Python and
  TypeScript (and every other extracted language) uniformly with one implementation,
  rather than five near-duplicate walkers. It delivers the plan's "minimal version:
  file + class scope"; lexical/block scope stays out of scope as the plan specifies.

## Pipeline integration — delivered (2026-05-21)

The scope-resolved pass is now wired into `codegraph index`. It is a **strategy
inside `ReferenceResolver.resolveOne`**, not a separate pass — `indexAll`
already calls `resolveReferencesBatched`, so adding the strategy needs no
`index.ts` or CLI change, and it matches the spec's Phase-2 ordering
("scope-index lookup ... import-resolver + name-matcher (fallback)").

Changes in `src/resolution/`:

- `index.ts` — `warmCaches()` builds a `ScopeIndex` over the extracted graph;
  `resolveOne` runs `resolveViaScope` as **Strategy 2** (after framework,
  before import / name-matcher) and returns immediately on a hit, because a
  bare name declared in the use site's own class/file IS its referent by
  language rules.
- `resolveViaScope` — gated to the SCIP-priority languages
  (`csharp`, `vbnet`, `java`, `python`, `typescript`/`tsx`); skips
  qualified/dotted/path-like names (the import resolver's job); resolves class
  scope first (shadows), then file scope. Requires an **unambiguous** match —
  multiple same-named declarations in a scope bail to the next strategy.
- **File-scope safety guard** — a file-scope match is restricted to
  `FILE_VISIBLE_KINDS` (function/class/type kinds). Members (`method`, `field`,
  …) are excluded: the delivered `ScopeIndex.fileScope` returns *every*
  declaration in a file, so without the guard a bare call in one class would
  wrongly bind to another class's same-named method. Class members stay
  reachable only through *class* scope.
- `enclosingClassQn` — walks `contains` edges up to the nearest class-like
  ancestor (`module` included, for VB); memoized per `fromNodeId`.
- `createEdges` — scope-resolved edges carry `provenance='scope-resolved'` and
  `confidence=0.75`, so `upsertGraphEdge` ranks them above heuristic edges.
- `types.ts` — `ResolvedRef.resolvedBy` gains `'scope'`.

### Tests — `__tests__/p05b-parity.test.ts` (+3, now 17)

`describe('scope-resolved resolution pass')` drives the real `CodeGraph.init({

## `runParity` runner + `codegraph parity` CLI — delivered (2026-05-21)

**Harness relocated to `src/parity.ts`.** The harness core was specced into
`__tests__/parity/parity-harness.ts`, but the `codegraph parity` CLI lives in
`src/bin/` and cannot import from `__tests__/`. Since the spec itself puts
`runParity` alongside the harness and `runParity` must be CLI-callable, the
whole module moved to `src/parity.ts`; `__tests__/parity/` is removed and
`p05b-parity.test.ts` imports from `../src/parity`.

- **`runParity(fixturePath): Promise<ParityRunResult>`** — locates the fixture's
  `.scip` (`index.scip`, else the first `*.scip`), ingests it into a throwaway
  DB via `persistScipIndex`, tree-sitter-extracts the same documents, and
  returns `buildParityReport` plus the inputs (`scipPath`, `files`, raw edge
  counts). Heavy modules (DB, persister, grammars) are imported lazily so a
  test that only needs the harness core stays light.
  - Deviation from the spec sketch: returns `ParityRunResult` (report + fixture
    metadata) rather than a bare `ParityReport`, because the CLI needs the file
    list and edge counts. The `opts.tolerance` sketch param is dropped —
    tolerance only matters at *assert* time (`assertEdgesEquivalent`), and the
    report already carries per-fingerprint call-site counts.
  - Fingerprints by node **name**, not qualified name: the SCIP and tree-sitter
    backends mint different QN shapes (`Catalog.ShapeCatalog` vs
    `Catalog::ShapeCatalog`), so a QN fingerprint reports everything divergent.

- **`codegraph parity --fixture <path>`** (`src/bin/codegraph.ts`) — runs
  `runParity` and prints a report: files compared, per-backend edge-row counts,
  shared / SCIP-only / tree-sitter-only fingerprint counts and kinds, and any
  shared fingerprint where tree-sitter under-counts SCIP's call sites. `--json`
  emits the raw `ParityRunResult`. Diagnostic only — exits 0 regardless of
  divergence (a missing fixture or no `.scip` exits non-zero).
